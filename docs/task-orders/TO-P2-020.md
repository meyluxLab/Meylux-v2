## 3. Required investigation

### 3.1 Re-open only with new evidence, not repeated summaries

For each unresolved gap G1–G8, determine whether any newer or previously unexamined **official provider source** materially resolves it. Cite exact source URLs, source/page identity, retrieval date, product family, relevant response fields, and any version/retrieval limitation. Do not repeat old findings as if they were new evidence. If no source resolves a gap, record the search scope and exact evidence still required.

### 3.2 Additional provider/product candidates

Investigate further plausible public-data providers not qualified in BR-P2-019, including candidates such as Phemex, BingX, KuCoin Futures, Kraken Derivatives, Deribit, Coinbase International, and any other candidate supported by credible official documentation leads. This list is exploratory, not a preferred shortlist; add or remove candidates based on documented instrument fit and evidence value.

For each candidate, first establish whether it offers a compatible linear/USDT-quoted perpetual product for both required asset scopes. Where its actual instrument identity, quote currency, settlement, margin/contract type, or product family is incompatible, classify it explicitly as identity-incompatible and do not substitute it silently. A different provider symbol may represent the same asset pair only when the provider's official instrument metadata proves the identity and existing contracts can preserve the distinctions truthfully.

For each plausible candidate, assess separately:
- Funding endpoint/fields, sign meaning, unit, event timestamp, history/cadence, retention and exact instrument family;
- current and historical OI endpoints/fields, explicit unit and aggregation/valuation basis, timestamp/period-boundary semantics, history/backfill/limits;
- direct provider-supplied Basis endpoint/field, exact definition/formula, sign, units, timestamp and coverage;
- whether all three facts apply to the same compatible product family for both BTC and SOL;
- provenance/raw fields, pagination, duplicates/replays, gaps, stale data, malformed values, contradictions, rate limits and outage semantics;
- truthful representation by existing frozen contracts and current normalization/persistence boundaries.

A field name or endpoint's existence is not qualification. Do not derive Basis locally under this Task Order. Do not use mark/index price, premium index, fair price, funding rate, or a different contract family's metric as a substitute for direct signed price-difference Basis.

### 3.3 S-04 and repository boundary

Re-inspect current repository contracts and persistence only where needed to verify claims or discover an already-governed authoritative joined read-back path. Preserve the distinction between provider documentation, repository implementation, contract representability, persisted availability and runtime status. No component-level persistence function or generic temporal check alone proves S-04 `AVAILABLE_PERSISTED`.
