## 5. Required Behavioral Boundary
### 5.1 Deterministic regime state
Implement a deterministic regime classification model whose inputs, factor semantics, thresholds/configuration, state labels, transition conditions, and output version are explicit and reproducible.

The model must:
- consume only evidence available at the observation/knowledge time;
- expose explicit state and calculation status;
- never infer missing values as zero or another fabricated value;
- preserve deterministic ordering of factor evaluation;
- make configuration an explicit input to the calculation;
- produce identical output for identical governed inputs and configuration.

Implementation-level state labels and factor composition may be selected by PRODUCER only where they remain within this Task Order and do not conflict with higher-order authority. The selected semantics must be documented and tested.

### 5.2 Hysteresis
Regime transitions must use explicit hysteresis semantics so ordinary boundary noise cannot silently cause non-deterministic or oscillating state changes.

The implementation must define and test:
- entry threshold(s);
- exit threshold(s);
- previous-state dependency, where used;
- exact-boundary behavior;
- insufficient-history behavior;
- contradictory factor behavior;
- deterministic transition precedence when multiple transitions are simultaneously eligible.

Hysteresis must not depend on wall-clock time, mutable global state, or hidden runtime state.

### 5.3 Multi-factor state
The regime result must distinguish:
- the resulting regime state;
- the factor/evidence inputs used;
- unavailable/insufficient factors;
- any deterministic aggregation or precedence rule;
- calculation version/configuration identity sufficient for replay and audit.

A missing factor must not be silently treated as a neutral or favorable factor unless the governed semantics explicitly define that behavior.

### 5.4 Venue-aware quantitative evidence
Implement venue-aware quantitative evidence comparison only as a quantitative evidence boundary.

The implementation must:
- compare compatible evidence using explicit canonical identity/time/context alignment;
- preserve venue context when supplied by the governing contract;
- reject or explicitly classify incompatible instruments, timeframes, timestamps, or evidence semantics;
- distinguish unavailable/insufficient evidence from a valid cross-venue comparison;
- avoid provider-specific wire semantics in canonical output;
- avoid becoming CMP-V2-VENUE-001 or implementing Venue Intelligence;
- avoid producing an intelligence-level venue recommendation.

No evidence may be fabricated merely because another venue has a corresponding record.

## 6. Numeric and Temporal Integrity
The implementation must comply with the established P4 numeric policy:
- Decimal is authoritative at the public quantitative boundary;
- floats/bools are not silently coerced into authoritative numeric values;
- non-finite values are rejected;
- no implicit rounding/quantization is introduced outside the governed numeric policy;
- no epsilon comparison is introduced unless already authorized by the applicable contract/policy;
- insufficient or unavailable values remain explicit;
- timestamps are timezone-aware UTC where timestamps are required;
- future observations must never influence earlier outputs.
