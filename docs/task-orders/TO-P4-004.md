## 1. Purpose

Implement the deterministic Market Structure Engine for STEP-P4-003 as a governed **fact-generation and state-machine engine** over trusted canonical Phase-3 inputs.

The implementation shall produce reproducible structural facts and lifecycle state without AI interpretation, opportunity scoring, trading authority, capital functionality, or future-Step functionality.

Within this Task Order, Producer is authorized to implement and test:

4. CHOCH detection and lifecycle/invalidation semantics;

## 3. Zero-Lookahead — Primary Correctness Invariant

`INV-V2-009` applies as a primary correctness invariant.

The implementation shall distinguish:

- **event location:** the historical bar/time to which a structural event belongs;
- **confirmation/knowledge time:** the earliest bar/time at which that event is deterministically knowable from the permitted information.

A confirmed historical Swing, BOS, CHOCH, MSS, FVG, Order Block, Breaker, or other structural fact must never be exposed at an earlier knowledge time than its evidence permits.

For any confirmation requiring later candles, the implementation must preserve the historical event location without backdating its observable/confirmed state.

No future candle, future state, future aggregate, or future-derived information may influence an earlier authoritative state.

Tests must exercise event timing, not merely final outputs.

---

## 4. Deterministic State-Machine Requirements

Every processed bar must have an explicitly reproducible state outcome.

At minimum, evidence must make it possible to reconstruct:

`input bar sequence → detected events → state transitions → final state`

For genuine ambiguity, the governed state is `UNCONFIRMED`; Producer shall not resolve ambiguity through undocumented heuristics or preference.

Duplicate structural events must be prevented according to the established contract. Lifecycle transitions and invalidations must be deterministic, replay-safe, and reproducible.

For quarantined/missing canonical bars, Producer shall not silently assume continuity or fabricate intermediary evidence. The behavior must remain explicit and deterministic, using the governed `UNCONFIRMED` semantics where the available evidence is insufficient.

## 5. Required Structural Semantics

### 5.1 Swing / HH / HL / LH / LL

Implement the established deterministic fractal swing semantics. Where confirmation requires future bars, preserve event-location versus confirmation-time distinction.

Classification must be reproducible from the same permitted input sequence and must not use future information earlier than allowed.

### 5.2 BOS

BOS behavior shall make the following observable and testable:

- broken structural level;
- triggering evidence and timestamp/knowledge time;
- whether close or wick constitutes the break, according to the established contract;
- duplicate-event prevention;
- invalidation/lifecycle behavior;
- direction/state transition.

Do not invent alternative semantics if the authoritative contract is silent; raise an Open Question for the affected semantic decision.

### 5.3 CHOCH

Apply the same temporal and deterministic discipline as BOS. A CHOCH must be tied to an explicit prior structural state and a deterministic break condition.

### 5.4 MSS

MSS shall be implemented as governed state-machine behavior, not as an informal label. Its trigger, prior-state requirement, confirmation timing, and resulting state transition must be explicit in implementation and tests.

### 5.5 Fair Value Gaps

Implement deterministic FVG detection and lifecycle:

`ACTIVE → PARTIALLY_MITIGATED → FULLY_MITIGATED`

No transition may depend on future information before that information becomes observable. Partial/full mitigation rules must be deterministic and evidence-backed.

### 5.6 Order Blocks / Breakers

Implement Order Block detection and deterministic lifecycle/invalidation. Breaker transitions must derive from governed structural/zone state, not discretionary interpretation.

### 5.7 Liquidity Pools

Represent liquidity pools as structural facts only. Do not convert them into opportunity signals, trade recommendations, confidence scores, or forecasts.

## 6. Pinned Scenario / State-Evolution Evidence

Rule 5 requires state-evolution evidence, not only final-output assertions.

Producer shall create and pin at minimum:

### Scenario A — 60-candle trend with BOS
A deterministic 60-candle scenario in which the expected structural sequence includes the governed BOS behavior.

Evidence must record, event-by-event:

- swing confirmations;
- HH/HL classification where applicable;
- structural state;
- BOS detection;
- confirmation/knowledge time;
- lifecycle/state transitions;
- exact expected state after each material event.

### Scenario B — 60-candle reversal with CHOCH
A deterministic 60-candle reversal scenario in which the expected structural sequence includes the governed CHOCH behavior.

Evidence must record the same event-by-event and state-transition-by-state-transition information.

For both scenarios:

- same input replay must reproduce the exact same event sequence and states;
- tests must be capable of detecting a wrong intermediate event timing even if a final output happens to match;
- expected results shall be pinned, not generated dynamically by the implementation under test.

A dedicated gap/quarantine scenario shall additionally verify deterministic behavior when canonical continuity is interrupted, including explicit `UNCONFIRMED` behavior where required.
