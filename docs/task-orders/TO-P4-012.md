## 2. Root-Cause Findings Established Before Activation

CONTROL's current evidence establishes the following:

1. `TO-P4-011 / AR-P4-018) verified deterministic Group-A P4 calculation and isolated PostgreSQL worker-path tests, but did not establish authoritative real-runtime Group-A population for the current governed VPS.
2. The current governed VPS checkout was at `02394ba59eece109c4bbe0ab7893d47523382fac), while authoritative `main) is `d7c3fa31cb092543440f2769ffbf9b6022c29a6a`; therefore prior runtime observations must not be treated as current-main implementation evidence.
3. The governed runtime contained:
   - `BINANCE:BTCUSDT) indicator rows with `source_ref=binance:binance-acquisition), but `venue_context=NULL);
   - CI-only rows with `TO-P4-011-CI:BTCUSDT) and `p4-011-ci:*) provenance, which are not authoritative market evidence;
   - 158 canonical candle rows and 2,996 raw acquisition rows, with Binance provider evidence present.
4. The canonical candle contract carries `provenance_id) but not venue/provider identity. The quantitative contextualization path therefore currently preserves source provenance without populating `QuantitativeContext.venue_context).
5. `contracts.acquisition.Provenance) already carries authoritative `ProviderIdentity), including `provider_id), and raw acquisition persistence retains `provider_id) together with `provenance_id). This is an existing upstream authoritative relationship and must not be reconstructed from instrument naming.
6. P5 Group-A configuration requires EMA periods `9,20,21,50,200), while the current P4 quantitative configuration exposes only a single EMA period (`20)). The existing P4 EMA engine itself is deterministic and parameterized; the unresolved issue is fact-population/configuration coverage, not permission to invent a new mathematical definition.
7. The current authoritative candle population is not sufficient to assume EMA-200 is calculable. The correct result for an insufficient EMA-200 history is explicit `INSUFFICIENT_DATA), not fabricated EMA-200 output.
8. The existing shared queue/restart foundation contains stale-pending recovery semantics. Any finding affecting the shared worker must be evaluated for actual applicability to the P5-004 acceptance boundary before modification; no generic shared-worker redesign is authorized merely because the method exists.

These findings are the starting evidence, not a prescribed implementation.

## 3. Required Outcome

The corrective cycle must establish all of the following, to the extent supported by authoritative evidence:

### 3.1 Authoritative venue/provenance resolution

Every newly persisted Group-A quantitative fact that is admitted as authoritative P5 evidence must carry a non-null venue when the authoritative source lineage establishes one.

The venue must be resolved from the existing authoritative provenance/provider relationship, not inferred from:

- `symbol);
- `BINANCE:BTCUSDT);
- `source_ref) text patterns;
- provider-specific instrument aliases;
- or other naming heuristics.

If the source lineage is missing, contradictory, or maps to multiple incompatible venues, the fact must remain explicitly unavailable/insufficient/contradictory according to the existing semantic vocabulary.

The correction must preserve:

- source provenance;
- identity;
- event_time;
- authoritative knowledge_time;
- timeframe;
- calculation/configuration version;
- append-only semantics.

No destructive rewriting of historical facts is permitted merely to make them appear corrected.

### 3.2 Complete Group-A EMA fact population

The authoritative P4 path must provide the EMA fact families required by the active P5 Group-A configuration, using the existing deterministic EMA implementation and without changing its mathematical definition.

At minimum, the corrective implementation must establish a governed mechanism for:

- EMA-9;
- EMA-20;
- EMA-21;
- EMA-50;
- EMA-200.

Where sufficient authoritative closed-candle history exists, the corresponding fact must be produced and persisted.

Where sufficient authoritative history does not exist, the fact must be represented explicitly as `INSUFFICIENT_DATA) / `INSUFFICIENT_HISTORY) under the existing P4 status/reason mechanism.

No EMA value may be synthesized solely to satisfy P5 configuration.

### 3.3 Real authoritative runtime population

The corrective cycle must not stop at CI fixtures.

CONTROL must be able to independently verify, through the governed SentinelX runtime boundary, a reproducible authoritative P4 → persistence path using actual persisted canonical/raw evidence already present in the governed environment.

The runtime acceptance must distinguish:

- real authoritative source rows;
- CI/test fixture rows;
- generated control probes;
- newly produced deterministic quantitative facts.

The acceptance evidence must show that Group-A facts written from authoritative runtime candles carry correct provenance, venue, timeframe, event_time and knowledge_time.

### 3.4 P5 EvidenceRef compatibility

The resulting persisted facts must be sufficient for P5 EvidenceRef construction with:

- source_family;
- record_id;
- identity_hash;
- event_time;
- knowledge_time;
- timeframe;
- venue.

P5 must not need to infer or reconstruct any of these from unrelated fields.

### 3.5 Multi-timeframe correctness

Primary and eligible higher-timeframe facts must remain independently identifiable and must satisfy:

`higher knowledge_time <= primary knowledge boundary`.

Post-boundary higher-timeframe facts must be rejected.

Different timeframes must not share an identity.

No-lookahead and replay/idempotency semantics must remain intact.
