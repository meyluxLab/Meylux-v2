## 5. Authorized Functional Scope

### 5.1 Moving Averages
Implement the indicators actually supported by authoritative repository contracts:
- EMA 9
- EMA 21
- EMA 50
- EMA 200
- SMA
- WMA
- HMA

Parameter handling must be explicit and deterministic. EMA initialization/warm-up semantics must be governed rather than left to library defaults.

### 5.2 Momentum
Implement:
- RSI 14
- MACD 12/26/9

Definitions, smoothing choices, seed/warm-up behavior and signal alignment must be explicit and reproducible.

### 5.3 Trend / Volatility
Implement:
- ATR 14
- ADX 14
- Bollinger Bands 20/2
- Supertrend

Candle field semantics must be explicit for formulas requiring OHLC. The Producer must not silently substitute another field when a required field is missing.

### 5.4 Statistical / Realized Volatility
Implement the statistical and volatility features justified by the authoritative contracts and roadmap boundary, including:
- Historical Volatility;
- realized/related volatility measures where the existing canonical input contract supports them;
- ATR percentile;
- deterministic expansion/compression inputs.

Definitions, observation windows, annualization or scaling conventions where applicable, and insufficient-history semantics must be explicit. If a requested measure lacks authoritative input semantics, do not invent them; record the issue as an open question/deviation and keep unsupported behavior explicit.

### 5.5 Volume / Activity
Implement:
- Volume SMA;
- RVOL;
- volume spike;
- volume climax.

These are quantitative activity facts, not signals or recommendations. Zero-volume and insufficient-history behavior must be explicit.

### 5.6 VWAP
Implement:
- VWAP;
- Anchored VWAP.

Anchored VWAP **must receive its anchor explicitly as input**. No hidden system clock, current-time inference, implicit session boundary, or mutable global state may determine the anchor.

Session/reset semantics must be deterministic and contract-backed.

## 7. No-Lookahead / Temporal Integrity

Indicator computation at observation time T may depend only on information legitimately available at T under the canonical input semantics.

No future candle, future volume, future timestamp, future aggregate, future session boundary or hidden wall-clock state may affect output for T.

Where a feature requires a completed observation period, the contract must distinguish incomplete from closed data rather than silently treating an incomplete period as final.

Tests must include an anti-lookahead regression strategy demonstrating that adding future observations cannot retroactively change already-emitted historical outputs except where an explicitly governed batch/recalculation semantic exists.

## 8. Data Integrity — Detect → Classify → Route

Invalid, contradictory, missing, malformed, quarantined or non-finite upstream data must not be silently repaired or substituted.

Required behavior:
`Detect → Classify → Route`

Examples:
- missing required OHLC field → explicit invalid/unavailable result or governed rejection;
- insufficient history → explicit status/reason, never fabricated numeric output;
- zero denominator → explicit mathematically invalid/unavailable outcome;
- non-finite input → reject/route according to contract;
- contradictory temporal ordering → explicit failure rather than sorting silently unless the authoritative contract explicitly permits normalization at this boundary;
- duplicate observations → deterministic handling according to contract; never accidental double counting.

## 9. Golden Vectors and Reference Integrity
