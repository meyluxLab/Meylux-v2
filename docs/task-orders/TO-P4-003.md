## 1. Authority and Trigger

This Task Order is issued under the Project Owner Directive **Targeted Correction and Reverification of STEP-P4-002**.

CONTROL's independent evidence reconstruction established that the historical `STEP-P4-002` closure record is not currently sustainable because `historical_volatility(window=1)` can reach a sample-variance denominator of `n - 1 = 0` after the existing positive-period validation accepts `window=1`.

This Task Order authorizes only the targeted correction of that confirmed defect and the directly necessary regression/reverification evidence.

The historical `TO-P4-002`, `BR-P4-002`, and `AR-P4-002` records remain traceable and must not be rewritten to erase their historical contents.

## 2. Objective

Correct the `historical_volatility(window=1)` boundary so that the public parameter/validation path deterministically rejects or otherwise handles the mathematically invalid boundary before any divide-by-zero operation can occur, consistent with the existing P4-001 numeric policy and P4-002 behavioral contract.

Add direct regression evidence proving the corrected boundary behavior and the absence of the identified divide-by-zero path.

This is a defect-correction-and-reverification Task Order. It is not a redesign task.

## 3. Authorized Correction Scope

The Producer may modify only the existing P4-002 implementation and directly necessary regression/evidence artifacts required to:

1. correct the `historical_volatility` parameter boundary identified by CONTROL;
2. preserve the existing historical-volatility mathematical definition for valid windows;
3. make the invalid boundary behavior deterministic and explicit;
4. prevent division by zero for the identified `window=1` path;
5. add direct regression coverage for `window=1`;
6. add only closely related boundary assertions necessary to demonstrate that the corrected validation remains deterministic and does not reintroduce the same divide-by-zero class;
7. update the Producer Build Report for this correction Task Order with actual evidence.

No broader P4-002 redesign is authorized.

## 4. Architectural and Contract Preservation

- `DOC-V2-ARCH-001`;

## 6. Required Implementation Behavior

For the confirmed boundary:

- `historical_volatility(window=1)` must not reach a zero denominator;
- invalid parameter semantics must be explicit and deterministic;
- no NaN/Inf or fabricated fallback value may be emitted;
- valid `window >= 2` behavior must remain mathematically unchanged;
- the correction must remain pure/deterministic and free of hidden system-time or mutable external state.

The exact implementation mechanism is Producer-level choice only if it preserves the authoritative contract and this boundary.

## 7. Required Regression Evidence

The Producer must add and execute direct regression coverage demonstrating at minimum:

1. `window=1` is handled according to the authoritative invalid-parameter semantics;
2. the call cannot produce a divide-by-zero failure;
3. no NaN/Inf/fabricated fallback leaks from the corrected path;
4. a valid `window >= 2` historical-volatility calculation remains correct against the existing controlled evidence;
5. the corrected path is deterministic across repeated execution.

Any additional assertion must be directly related to the corrected boundary and justified in the Build Report.
