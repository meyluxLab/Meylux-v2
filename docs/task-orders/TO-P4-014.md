## 1. Authority and objective

The next governed Phase-5 boundary is `STEP-P5-006 — Group C: Volume, Volume Profile`, covering `S-03` Volume Analyst and `S-17` Volume Profile Reasoner.

The authoritative roadmap identifies the Step gate as `PRQ-1` plus `PRQ-2 (trade)`. Current repository evidence establishes that:

1. the P4 `VolumeProfileEngine` exists and is defined over `CanonicalTrade`;
2. the authoritative `volume_profile_sessions` persistence object exists;
3. the current evidence does not establish an authoritative runtime population of that P4 surface;
4. the P5 Fact Requirements Matrix therefore does not admit Group-C facts as `AVAILABLE_PERSISTED`;
5. the existing Binance Spot acquisition path has real `AVAILABLE / TRADE` evidence, but this Task Order must establish whether the existing canonical-trade path is sufficient for the required Group-C P4 workload rather than assuming that provider availability equals authoritative P4 fact delivery.

This Task Order therefore resolves the specific upstream Group-C prerequisite required to make `STEP-P5-006` legitimately executable. It does not implement the P5 specialists themselves.

The governing outcome is:

> **Establish, with real evidence and without changing frozen P4 mathematics, an authoritative P4 Group-C fact surface sufficient for the later P5-006 acceptance boundary, or surface the exact remaining prerequisite through its owning boundary without silently weakening the requirement.**

## 2. Required outcome

Producer shall inspect, implement where necessary, test, and document the minimum bounded P4 work required to establish:

### 2.1 Volume facts for S-03

A real, authoritative P4 fact path sufficient for the P5 S-03 boundary, including the existing deterministic volume/RVOL-related semantics required by the Phase-5 roadmap.

The implementation must preserve explicit insufficient/unavailable semantics where the actual evidence cannot support a stronger result.

### 2.2 Volume Profile facts for S-17

A real P4 operational path using authoritative `CanonicalTrade` input to produce and persist the existing P4 Volume Profile session facts required by the P5 S-17 boundary, including the session information needed for:

- current-session Value Area interpretation;
- POC / VAH / VAL / HVN / LVN evidence where the existing P4 semantic contract supports them;
- previous-session POC comparison only where the required minimum of two persisted sessions is actually established;
- deterministic identity, provenance, timeframe/session boundaries and replay/idempotency.

No new mathematical definition may be invented merely to satisfy P5.

### 2.3 P5 dependency evidence

The resulting evidence must be sufficient for CONTROL to determine whether:

- `PRQ-1 Group-C` is `ESTABLISHED / VERIFIED`; and
- the trade-input portion of `PRQ-2` required by `STEP-P5-006` is actually satisfied for the intended governed acceptance boundary.

A provider adapter being capable of producing a trade event is not by itself sufficient evidence of an authoritative P4 persisted fact surface.
