This Task Order establishes and activates the normal governed implementation boundary for `STEP-P5-003`.

## 3. Required Outcome

The completed implementation must provide, at minimum:

1. A real bounded Stage-1 runtime path from an authoritative Input Snapshot to specialist execution and append-only specialist persistence.
2. Deterministic ordering and bounded concurrency.
3. Config-driven timeout handling.
4. Failure isolation so one specialist failure does not corrupt unrelated work.
5. Idempotent processing and duplicate-safe persistence.
6. Retry only for explicitly classified infrastructure/transient failures; no retry loop for semantic/input failures.
7. Explicit overload/backpressure behavior.
8. A real DLQ/failure route consistent with existing project contracts.
9. A deterministic read-back path for persisted specialist output.
10. A new `worker-specialist` compose/runtime service only if required by the selected implementation design; it must be a real worker, not a placeholder process.
11. Required WRK/QUE/DEP/OBS/SEC evidence surfaces consistent with existing project conventions.
12. A complete `S-10` deterministic implementation consuming the Step-2 authoritative Input Snapshot / FRM boundary and the now-verified P3 quality/acquisition evidence.
13. `S-10` output that can represent:
   - overall quality classification using the defined worst-status semantics;
   - explicit non-`VALID` inputs;
   - `STALE_INPUT`;
   - `INCOMPLETE_HISTORY`;
   - `CONTRADICTORY_INPUT`;
   - `UNAVAILABLE_INPUT`;
   - resolvable evidence references.
14. No fabricated market/quality evidence and no substitution of operational timestamps for authoritative `knowledge_time`.
15. Replay determinism: equivalent input and configuration must produce equivalent deterministic output identity.
16. A real performance/resource baseline for the Step, using a documented workload, environment, sample size, percentile and method. The baseline is evidence, not an invented target.

## 5. Architectural and Semantic Constraints

Implementation must preserve:

- `DOC-V2-ARCH-001` and its hierarchy.
- Stage-1 independence: `S-10` receives only the authoritative shared Input Snapshot and the evidence references/facts explicitly allowed by its contract.
- Zero lookahead: no input with `knowledge_time > snapshot.as_of` may enter the specialist.
- Deterministic behavior where mathematically/semantically required.
- No NaN/Inf leakage.
- Provider-neutral evidence semantics.
- Explicit unavailable/invalid/stale/contradictory behavior.
- Append-only authoritative specialist persistence.
- Evidence provenance and resolvability.
- Separation of confidence from data quality.
- Existing least-privilege and database security boundaries.
- No competing truth store.

The Producer may choose the implementation mechanism, decomposition, queue model and internal design provided these constraints and the required outcome are preserved.

## 6. S-10 Semantic Boundary

`S-10` is a reference specialist for the runtime harness. It must not manufacture upstream quality evidence.

For every consumed input/evidence item, the implementation must preserve the distinction between:

- source/provider event time;
- observation/receipt time;
- validation time;
- persistence/logging time;
- wall-clock execution time;
- `knowledge_time`.

The authoritative P3 quality/acquisition evidence established by `TO-P3-009` is the source for the quality/evidence surface. Legacy or genuinely unavailable evidence remains explicitly unavailable; it must not be made eligible by assigning a convenient timestamp.

Where a required S-10 input is unavailable under the Step-2 FRM, the specialist must emit the defined explicit unavailable/insufficient status rather than inventing a value.

## 7. Failure, Retry, DLQ and Replay Semantics

The implementation must explicitly classify at least:

- malformed input;
- missing required input;
- stale input;
- contradictory input;
- unavailable input;
- semantic/contract failure;
- transient infrastructure failure;
- timeout;
- duplicate delivery;
- persistence conflict;
- overload/backpressure.

Each class must have deterministic handling.

Infrastructure retry must be bounded. Semantic failures must not be retried indefinitely.

DLQ records must preserve enough information to diagnose and deterministically reproduce the failed processing decision without becoming a second authoritative truth store.

Duplicate delivery must not create duplicate authoritative specialist outputs.

Restart with pending work must preserve correctness and idempotency.
