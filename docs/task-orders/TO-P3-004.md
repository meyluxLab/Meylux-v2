## 2. Objective

Establish market-semantic correctness including price, OHLC, quantity, spread and precision validation within the existing P3 foundation.

P3-004 consumes the verified P3-001 validation/precision foundation and the verified P3-002/P3-003 validation boundaries. It must not recreate, replace, weaken, duplicate, or silently reinterpret those foundations.

## 3. Authoritative Scope Boundary

Within the authorized boundary, establish deterministic validation behavior for:

1. price validity semantics;
2. price positivity semantics and invalid/non-positive price detection where governed by the existing semantic model;
3. deterministic OHLC internal consistency validation, including applicable relationships such as `high ≥ low`, `high ≥ open`, `high ≥ close`, `low ≤ open`, and `low ≤ close`;
4. quantity validity semantics;
5. volume/quantity consistency checks where defined by existing contracts;
6. rejection or classification of invalid quantity/volume values according to the existing validation framework;
7. bid/ask relationship validation where bid/ask data is applicable;
8. spread integrity and detection of invalid spread relationships;
9. tick/lot precision and scale validation where authoritative information exists;
10. deterministic reuse of the existing `Decimal` / precision doctrine established by P3-001;
11. deterministic precision handling without introducing a competing numeric policy;
12. deterministic findings and outcomes using the existing `ValidationOutcome` taxonomy;
13. evidence-preserving reporting sufficient for independent CONTROL audit.

No additional market rule may be invented. Where a required market-specific parameter is not authoritatively defined in the repository, the Producer must not invent it. Such a parameter must remain an explicit caller-supplied / governed input consistent with the established P3-001 design pattern, or the exact gap must be surfaced to CONTROL as an Open Question / governed input requirement.

## 5. Validation and Data-Quality Semantics

Market-semantic findings must use the existing P3 validation foundation and the existing `ValidationOutcome` taxonomy. No new taxonomy value may be introduced by this Step.

Findings must remain deterministic, evidence-based and traceable to actual input evidence. Missing, stale, invalid, contradictory or incomplete evidence must remain explicit; no fabricated fallback values or silent repair are permitted.

P3-004 may emit governed validation results/findings needed for downstream routing, but it must not implement responsibilities owned by later Steps.

## 7. Deterministic Data Rules

- Validation behavior must be deterministic and reproducible.
- Pure validation logic must not depend on wall clock, network, filesystem, database I/O, mutable global state, or other uncontrolled runtime state unless an existing authoritative contract explicitly requires it.
- Use the approved `Decimal` / precision doctrine; do not introduce forbidden float behavior into authoritative validation.
- No silent repair, interpolation, fabrication, deletion, normalization, or promotion of invalid evidence.
- No invented market parameters, thresholds, tick sizes, lot sizes, precision scales, or spread policies.
- No NaN/Inf leakage into authoritative outputs.
- No fabricated market values.
- All findings and outcomes must be traceable to actual input evidence.
