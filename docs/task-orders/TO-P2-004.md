## Objective

Integrate the verified Binance and MEXC acquisition adapters into the Phase 2 collector and establish the governed raw/staging persistence and replay-safety boundary required by `PH-P2`.

## Authoritative Scope

1. Collector integration for the existing provider-neutral acquisition boundary and verified Binance/MEXC adapters.
2. Raw/staging persistence required for acquisition evidence, without promoting raw provider payloads to authoritative analytical truth.
3. Bounded queue/backpressure behavior for acquisition transport.
4. Duplicate/idempotency controls and replay-safe persistence semantics.
5. Provider/source sequencing and reconnect handling required to preserve acquisition ordering and replay safety.
6. Required database schema/migrations/models/repositories for the Step, using the project's existing persistence architecture and PostgreSQL/TimescaleDB boundary where already established.
7. Required worker/collector integration using existing queue/worker conventions; do not redesign the queue foundation.
8. Evidence-compatible observability for collector, persistence, backpressure, duplicate/idempotency, and provider failure states using existing observability conventions.
9. Deterministic tests for persistence mapping, idempotency/replay behavior, sequencing, backpressure bounds, provider isolation, and failure recovery.
10. Required repository traceability and Build Report `BR-P2-004`.

- `CMP-P2-001` — Provider-Neutral Acquisition Boundary;
