## 2. Independent verification of AR-P4-007 corrections

### 2.1 F-01 correction — materially present

The audited implementation now contains `_derived_context(...)`, which derives context when explicit context is absent.

Observed behavior:

- Volume Profile derives symbol, contributing timestamps and ordered provenance IDs.
- Bar Delta derives symbol, contributing timestamps and ordered provenance IDs.
- CVD accumulates ordered provenance lineage and timestamps across the processed bar sequence.
- Derivatives derives context from current/prior canonical derivative observations in semantic input order.
- Explicit caller-supplied context remains authoritative because `_derived_context` returns it unchanged.
- timeframe and venue_context are not fabricated.

The focused tests directly cover Volume Profile, Bar Delta, cumulative CVD and Derivatives provenance propagation.

### 2.2 F-02 correction — materially present

`ClosedBar.__post_init__` now enforces the half-open interval:

`[start_time, end_time)`

CVD rejects:

`next.start_time < previous.end_time`

and therefore permits adjacent bars sharing an endpoint without allowing a trade to belong to both bars.

CVD also enforces one instrument across the complete non-empty bar sequence.

The focused tests directly cover end-boundary rejection, adjacent ownership, valid same-instrument adjacency, no double counting and cross-instrument CVD rejection.

These two original findings are therefore considered **corrected at implementation level**, subject to the new blocking findings below.

## 3. Blocking Finding F-03 — Bar Delta cross-instrument aggregation

### Observed behavior

`OrderFlowEngine.bar_delta()` validates that every item is a `CanonicalTrade`, then derives context using:

`instrument_id=xs[0].instrument_id`

but it does not reject later trades whose `instrument_id` differs from the first trade.

Consequently, an input such as:

- BTCUSDT BUY quantity 7;
- ETHUSDT SELL quantity 3;

is accepted and produces a single Delta of 4 while the derived result context identifies the series as BTCUSDT.

This is semantically unsafe evidence aggregation: quantities from different instruments are combined into one fact and the result is labelled with only the first instrument.

### Why this blocks verification

The canonical trade contract carries instrument identity, and the established P4 quantitative validation pattern rejects mixed instruments for ordered quantitative series. The same integrity boundary is already enforced by Volume Profile, ClosedBar, CVD and absorption.

Allowing mixed instruments in Bar Delta creates a deterministic but invalid quantitative fact and undermines the provenance/context correction just completed.

### Required correction

Within TO-P4-005:

1. enforce one instrument across the complete Bar Delta trade input when the input is non-empty;
2. reject contradictory cross-instrument input explicitly;
3. do not sort, drop, coerce, or silently repair the offending trade;
4. add direct regression coverage for:
   - valid same-instrument Bar Delta;
   - cross-instrument Bar Delta rejection;
   - derived context symbol remains the sole validated instrument;
5. preserve existing Delta semantics and no new contract/Stable ID.
