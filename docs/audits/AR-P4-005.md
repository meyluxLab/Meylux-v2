## 3. Blocking Finding F-07 — Normal insufficient structure is incorrectly emitted as UNCONFIRMED

**Authority:** DOC-P4-002 §7.4, §7.5 and §6; TO-P4-004 §4, §5.1 and §13.

The ratified state machine explicitly distinguishes insufficient confirmed structure from ambiguity:

- `NEUTRAL` applies when insufficient confirmed structure exists and there is no continuity break or contradictory evidence.
- `UNCONFIRMED` is reserved for governed ambiguity/transition cases such as continuity boundaries, equality ambiguity, CHOCH transition, or unavailable/contradictory required references.
- The first confirmed swing has no comparative classification and does not establish a directional structure state.

The current implementation's `_derive_state()` returns `UNCONFIRMED` whenever the latest confirmed high or low lacks a classification. That conflates normal warm-up/insufficient structure with semantic ambiguity.

The pinned bullish/reversal golden traces consequently lock this mismatch into expected output. For example, when the first same-type swing is confirmed and the structure is still merely insufficient for a directional state, the trace records `UNCONFIRMED`; DOC-P4-002 §7.4 and pinned Scenario A require `NEUTRAL` before sufficient paired directional structure exists.

This is a semantic implementation defect, not merely a missing test. The tests are deterministic against the wrong semantic state.

**Required correction:** distinguish normal insufficient/warm-up structure from genuine ambiguity; emit `NEUTRAL` for ordinary insufficiency with no governed ambiguity/transition; preserve `UNCONFIRMED` for the cases specified by §7.5; update both pinned 60-candle traces; add direct regressions for the first-unclassified-swing/warm-up boundary.

**Disposition:** BLOCKING.

## 4. Blocking Finding F-08 — CHOCH append-only invalidation remains unimplemented/unproven

**Authority:** TO-P4-004 §2A and §2 item 4; DOC-P4-002 §8, §9, §10 and §16.

TO-P4-004 explicitly authorizes CHOCH lifecycle/invalidation semantics. The current engine stores BOS and MSS facts in `active_break_facts`, but CHOCH creation does not add the CHOCH event to that structure. The implementation therefore has no corresponding active-fact path for later CHOCH invalidation.

The final test suite's direct structural-invalidation regression exercises a BOS source identity only. No direct CHOCH append-only invalidation regression exists.

The Producer handoff claimed that BOS/CHOCH/MSS structural facts now receive append-only invalidation facts, but the current repository evidence does not support that claim for CHOCH.

**Required correction:** resolve the governed CHOCH invalidation lifecycle within DOC-P4-002; preserve the original CHOCH immutably; where later authoritative evidence invalidates/contradicts the CHOCH under the governed semantics, emit a distinct invalidation/state-transition fact referencing the CHOCH identity; add direct regression evidence.

**Disposition:** BLOCKING.
