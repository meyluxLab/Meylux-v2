## 4. Blocking Finding F-01 — provenance/context is not automatically preserved

### Requirement

P4-001 quantitative semantics establish provenance/timeframe/symbol/venue context preservation where contractually required. `DOC-P4-003` and `TO-P4-005` require provenance/traceability appropriate to authoritative quantitative results.

The existing P4 indicator implementation provides the established pattern: canonical input provenance is converted into `QuantitativeContext` containing source reference, timestamp, timeframe and symbol.

### Observed implementation

`volume_orderflow_derivatives.py` accepts an optional `QuantitativeContext`, but does not construct that context from the canonical input provenance when the caller omits it.

Examples:

- Volume Profile accepts canonical trades containing `provenance_id`, but returned `CalculationResult.context` remains `None` unless the caller manually supplies context.
- Bar Delta/CVD similarly do not derive result context from the trade provenance.
- Derivatives results do not derive context from `CanonicalDerivatives.provenance_id`, timestamp or instrument identity.

Thus a valid canonical evidence chain can enter the engine with concrete provenance and leave the authoritative result without that provenance being carried into the quantitative result context.

### Why this blocks verification

This is not merely documentation. It weakens the deterministic evidence lineage of the new quantitative facts and diverges from the established P4 quantitative context pattern.

The implementation should not require every caller to reconstruct provenance manually when the authoritative canonical input already contains it.

### Required correction

Within the existing contract boundary:

1. derive deterministic `QuantitativeContext` from the relevant canonical input(s) when explicit context is not supplied;
2. preserve the established fields at minimum: source reference, timestamp, symbol/instrument identity and applicable timeframe/venue context;
3. for multi-input results, define deterministic provenance composition without fabricating or silently discarding source identity;
4. add direct regression tests proving result context survives the Volume Profile, Order Flow/CVD and Derivatives paths;
5. preserve explicit caller-supplied context semantics only where the governing contract permits it;
6. do not introduce a new Stable ID or redesign the quantitative contracts.

## 5. Blocking Finding F-02 — ClosedBar/CVD boundary permits deterministic double counting

### Requirement

The quantitative foundation requires contradictory temporal ordering to be rejected and duplicate observations not to be silently double-counted. `TO-P4-005` additionally requires deterministic temporal correctness and no-lookahead.

### Observed implementation

`ClosedBar.__post_init__` currently accepts a trade when:

`start_time <= trade.timestamp <= end_time`

CVD accepts adjacent bars when:

`next.start_time == previous.end_time`

because only `next.start_time < previous.end_time` is rejected.

Consequently, a trade timestamp exactly equal to the boundary can legally belong to both adjacent closed bars:

- Bar A: `[t0, t1]`
- Bar B: `[t1, t2]`

A trade at `t1` is valid in both bars.

CVD then computes Delta for both bars and counts that same canonical trade twice.

This is a deterministic, reproducible duplicate-observation path rather than a hypothetical implementation concern.

### Additional integrity gap

CVD does not enforce a single instrument across the sequence of non-empty `ClosedBar` inputs. Each individual bar validates its own trades, but the CVD sequence itself can combine:

- BTCUSDT Delta in one bar;
- ETHUSDT Delta in the next bar;

without rejection or explicit classification.

That produces a mathematically deterministic but semantically invalid cross-instrument cumulative series.

### Why this blocks verification

The result can silently represent a different quantity from the intended cumulative order-flow series while all tests remain green. Rule 5 explicitly requires maximum practical correctness and duplicate/contradictory evidence must not be silently absorbed.

### Required correction

Within `TO-P4-005`:

1. establish an explicit non-overlapping ClosedBar temporal convention;
2. reject a trade at the exclusive end boundary or otherwise enforce a single canonical ownership rule for boundary timestamps;
3. reject any cross-bar temporal overlap;
4. enforce one instrument across the complete CVD sequence when instrument identity is available;
5. add direct tests for:
   - trade exactly at the first bar's end boundary;
   - adjacent bars with the same boundary;
   - duplicate-boundary trade cannot contribute twice;
   - cross-instrument CVD input is rejected;
   - valid adjacent same-instrument bars remain accepted;
6. preserve deterministic ordering and do not sort or silently repair the input.
