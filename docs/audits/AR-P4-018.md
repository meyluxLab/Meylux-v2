## 3. Requirement and semantic verification

### 3.1 Group-A fact surface

The implementation composes the existing deterministic P4 indicator library rather than introducing a P5 calculation path.

The independently inspected fact vocabulary is:

- EMA;
- RSI-14;
- MACD / MACD signal / MACD histogram, 12/26/9;
- ADX-14;
- Bollinger middle / upper / lower / bandwidth, 20/2;
- ATR-14;
- historical volatility;
- ATR percentile;
- volatility expansion ratio.

The underlying indicator functions and golden-vector implementation were not redesigned.

### 3.2 Multi-timeframe and no-lookahead

The final orchestration validates higher-timeframe candle sequences for:

- closed-candle state;
- instrument consistency;
- timeframe consistency and key/candle agreement;
- strict ordering;
- non-overlapping intervals;
- primary/HTF distinction; and
- `close_time <= primary knowledge boundary`.

A post-boundary HTF candle is rejected rather than silently truncated.

An HTF fact uses its own closed-candle `close_time` as both `event_time` and `knowledge_time`, while persistence independently enforces that this value does not exceed the primary knowledge boundary.

### 3.3 Knowledge-time semantics

The existing `TO-P4-010` rule remains authoritative:

`knowledge_time = authoritative closed-candle event_time`

The final persistence path rejects an orchestration result whose primary `knowledge_time` is not UTC or does not equal `as_of`.

No `persisted_at`, receipt time, wall-clock time, database commit time or migration time is substituted.

### 3.4 Identity and provenance

Each persisted Group-A indicator fact carries:

- logical fact name;
- deterministic identity;
- symbol;
- timeframe;
- event time;
- source provenance;
- calculation/configuration version;
- calculation status/reason;
- deterministic payload/value representation.

The existing append-only `meylux.calculated_indicator_vectors` boundary is reused. No competing P5 truth store was introduced.

### 3.5 Replay and append-only behavior

Indicator inserts retain `ON CONFLICT(identity_hash) DO NOTHING`.

The final integration evidence verifies that replay through the same governed Worker path does not create additional primary or HTF rows and preserves deterministic identities.

No UPDATE, DELETE or historical backfill was introduced.
