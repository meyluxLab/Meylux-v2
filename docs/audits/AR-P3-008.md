## 3. Finding F1 — Duplicate Quality-Log Write in Canonical Persistence

**Severity:** BLOCKING

In `src/meylux/persistence/canonical.py`, `CanonicalPersistence.persist()` defines the quality-log INSERT and executes it twice when `assessment is not None`.

The implementation contains two consecutive `if assessment is not None:` blocks that both execute the same `data_quality_logs` INSERT with the same values.

Therefore, a single newly inserted canonical record with a supplied QualityAssessment produces two quality-log rows.

This violates the intended deterministic audit trail and is not justified by the Task Order. It also creates duplicate evidence for one canonical persistence operation.

The current dedicated tests only assert that a quality-log execution occurred; they do not assert exactly one quality-log record/write.

### Required correction

1. Ensure one canonical persistence operation with an assessment produces exactly one corresponding `data_quality_logs` row.
2. Remove the duplicate execution without changing the intended transaction boundary.
3. Add a deterministic regression test that fails if the quality-log write occurs more than once for one successful canonical insertion.
4. Re-run the dedicated P3-008 suite and full foundation regression.
5. Produce updated CI evidence for the corrected implementation.

**Acceptance condition:** the corrected implementation contains one intentional quality-log write per new canonical persistence operation with assessment, and automated coverage proves the duplicate write cannot recur.
