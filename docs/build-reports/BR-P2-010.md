## 3. Semantic correction

### 3.1 MEXC WebSocket

The existing MEXC protobuf kline representation supplies:

- interval;
- windowStart;
- windowEnd;
- openingPrice;
- closingPrice;
- highestPrice;
- lowestPrice;
- volume;
- amount;
- event/send timing.

It does not provide an authoritative finality flag in the governed acquisition representation.

The normalization path now parses the available structural/time/numeric fields first and then explicitly rejects:

`ValidationCode.PROVIDER_FIELD / field=is_closed`

with the message:

`MEXC provider finality is unavailable; candle is not canonically eligible`.

The `CanonicalCandle(...)` constructor is therefore unreachable for this MEXC branch.

### 3.2 MEXC REST

The MEXC adapter already preserved the original REST row. The correction additionally preserves the requested interval so the acquired observation retains sufficient provider-specific context for deterministic normalization inspection.

The original row remains intact; it is not rewritten into a synthetic canonical candle.

A structurally valid REST row therefore reaches normalization as acquisition evidence, but is rejected because authoritative provider finality is unavailable.

The REST close-time field remains close-time evidence. It is not converted into `is_closed=True`.

## 5. Deterministic validation precedence

The correction establishes the following deterministic precedence for the MEXC candle path:

1. acquisition/envelope availability and provenance;
2. provider candle payload shape and required timeframe context;
3. timestamp structural validity;
4. OHLCV primitive validity;
5. provider-finality eligibility;
6. canonical construction.

Therefore, when unavailable finality coexists with a malformed structural field, the structural failure is classified first. A structurally valid candle then reaches the explicit finality rejection.

This is deterministic and independent of:

- dictionary iteration order;
- exception ordering;
- incidental provider payload ordering;
- wall-clock time;
- replay timing.

The regression suite explicitly covers malformed `windowEnd` versus unavailable finality and verifies that the result is stable.
