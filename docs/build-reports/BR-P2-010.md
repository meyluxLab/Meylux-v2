## 6. Deterministic validation precedence

The precedence rule is:

1. Reject unsupported provider identity first.
2. For MEXC candle payloads with recognizable MEXC candle shape, reject unavailable provider finality before parsing timing, OHLCV, or other candle semantic fields.
3. Therefore, when unavailable finality coexists with malformed windowStart, malformed windowEnd, windowEnd <= windowStart, malformed OHLCV, or contradictory metadata, the deterministic primary classification is the unavailable-finality is_closed issue.
4. If the payload does not even expose a recognizable MEXC candle structure, existing structural/required-field validation remains responsible for the classification.

This precedence is deterministic because it does not depend on:

- mapping/dictionary ordering;
- exception ordering;
- runtime timing;
- local clock;
- object construction;
- or incidental iteration order.

The rule is encoded directly in the MEXC branch and regression-tested.
