## CONTROL Correction — Rate Saturation
CONTROL identified that the original `_RateFilter` uniformly rejected records after the normal per-second budget, which could silently discard `ERROR` and `CRITICAL` diagnostics. The first correction kept the existing bounded rate limit for lower-severity events while allowing `ERROR` and `CRITICAL` records through when the normal budget was exhausted. CONTROL subsequently demonstrated that this created an unlimited bypass, so the second correction below bounds both severities explicitly.

Tests were extended to verify: lower-severity events remain bounded; `ERROR` remains observable under saturation; `CRITICAL` remains observable under saturation; and the rate filter retains only fixed scalar counters with no buffering collection.

## Correction 2 — Bounded Critical Severity Reservations
CONTROL identified that the previous correction allowed `ERROR` and `CRITICAL` to bypass the rate budget without bound. The rate filter was corrected to retain the normal lower-severity budget while reserving exactly one bounded emission slot per second for `ERROR` and exactly one for `CRITICAL`. Repeated events at either severity are suppressed after their reserved slot is consumed; no emergency queue, buffer, retry path, or alternate logging path was introduced.

Tests were extended to verify actual emitted counts for 10,000 repeated events at each relevant severity with `max_events_per_second=1`. The stress test uses a test-only controlled clock so all emissions remain inside one deterministic rate window. The rate filter retains only fixed scalar counters and has no buffering collection.
