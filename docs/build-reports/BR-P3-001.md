## 4. Correction Summary

### F-01 — Authoritative Data-Quality Taxonomy

Corrected `ValidationResult` to the architecture-authoritative seven outcomes only:

`VALID / DEGRADED / STALE / INCOMPLETE / CONTRADICTORY / REJECTED / UNAVAILABLE`

Removed the previously introduced `INVALID`, `UNSUPPORTED`, and `QUARANTINED` members from this canonical validation-result taxonomy. `REJECTED` is the deterministic outcome for validation findings that are not merely missing required evidence.

### F-02 — Provenance Negative Evidence

Added `validate_provenance()` as a deterministic canonical-boundary check covering missing provenance, invalid provenance type, empty immutable reference rejection, and valid immutable provenance acceptance. No fallback provenance is fabricated.

### F-03 — ValidationOutcome Mapping

Added `validation_outcome()` to deterministically map primitive findings to the declared outcome model: no findings → `VALID`; missing/null required evidence, missing provenance, or missing lineage → `INCOMPLETE`; other validation findings → `REJECTED`. Later-step freshness, contradiction, degradation, availability, repair, quarantine and persistence behavior remain outside this Step.

### F-04 — Precision Evidence Boundary

No competing precision policy was invented. The implementation relies on the existing authoritative canonical precision/scale semantics: finite `Decimal`, float rejection, source-scale preservation, explicit precision metadata, and scale rejection without rounding or quantization.
