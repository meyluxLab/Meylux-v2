## 2. Root-cause and design findings

### 2.1 Instrument identity and venue are separate evidence

Current P4 facts can retain a venue-qualified instrument identifier such as BINANCE:BTCUSDT while the P5 Group-A configuration uses the underlying symbol BTCUSDT. Exact-string matching alone would silently miss valid facts. Conversely, deriving venue from the prefix would violate the explicit no-inference rule.

The specialist now matches a qualified instrument identifier only when its prefix agrees with the separately supplied, explicit metadata venue; the EvidenceRef venue must also agree with that metadata. Unqualified BTCUSDT remains eligible only with explicit venue context. A qualified prefix that conflicts with explicit venue evidence raises a semantic error rather than being silently repaired or relabeled.

Group-A findings are keyed independently by symbol, venue and timeframe. This prevents Binance and MEXC facts for the same symbol/timeframe from colliding or being mixed into one directional calculation. The configured venues are BINANCE and MEXC; absence of a venue's facts produces explicit missing/insufficient findings and does not trigger acquisition or fabrication.

### 2.2 Existing P4 mathematics remains authoritative

The specialist layer interprets persisted P4 facts only. It does not calculate EMA, RSI, MACD, ADX, Bollinger Bands, ATR, historical volatility, ATR percentile or volatility expansion ratio. It does not call P4 indicator functions and does not use another specialist's output as input.

The configured EMA period set is 9, 20, 21, 50 and 200, with 20 as the primary EMA used by PRICE_VS_MA and the MTF direction rule. Missing periods remain explicit. MA_ALIGNMENT reports INSUFFICIENT_DATA when too few periods are available and PARTIAL when a usable subset exists but the configured set is incomplete. In particular, missing EMA-200 is never synthesized.

### 2.3 Evidence and time context fail closed

Consumed facts must have a complete EvidenceRef with source family, record ID, SHA-256 identity hash, event time, knowledge time, timeframe and venue. Timestamps must be explicit UTC datetimes. The metadata event/knowledge context and the EvidenceRef venue/timeframe/event/knowledge fields must agree.

Missing, malformed, invalid, non-finite, stale, contradictory and post-boundary evidence remains classified; no fallback numeric value is invented. A symbol-qualified identity inconsistent with explicit venue evidence is rejected. Multi-timeframe interpretation evaluates each venue separately and rejects higher-timeframe facts whose semantic closed-candle boundary exceeds the primary closed-candle boundary or whose knowledge_time exceeds the primary knowledge boundary. Canonical candle event_time remains open-time provenance and is not rewritten.

Canonical candle source-row event_time remains the open boundary in metadata and EvidenceRef. For temporal alignment only, canonical candle facts require an explicit UTC close_time in the persisted payload; S-01 price/indicator alignment and S-06 primary/higher-timeframe no-lookahead comparisons use this closed-candle boundary, while knowledge_time remains a distinct boundary. Missing or malformed close_time is rejected rather than inferred from timeframe duration or repaired from event_time. These checks do not independently prove that every EvidenceRef resolves to a live authoritative database row; that final source-row resolution remains part of CONTROL's runtime acceptance below.

### 2.4 Bounded corrections from the independent CONTROL audit

The first independent audit identified two semantic defects: equal-valued exact EMA period records and legacy EMA aliases were falsely treated as multiple authoritative facts, and candle open-time metadata was being used as the closed-candle temporal boundary.

The corrected implementation selects exact EMA period records as the configured authority; permits legacy EMA only as the primary-period fallback when the exact configured alias is absent; accepts equal valid exact/legacy values at the same event boundary; preserves an explicit CONTRADICTORY state for conflicting valid aliases; and prevents a later legacy alias from superseding an available exact alias. An exact alias with non-valid fact status or a non-valid calculation payload (including INSUFFICIENT_HISTORY) remains authoritative and cannot be replaced by a valid numeric legacy alias. Canonical candle open-time provenance remains unchanged, while explicit UTC close_time is used for S-01/S-06 temporal alignment and no-lookahead. knowledge_time remains independent.

Regression tests cover equal/conflicting valid aliases, legacy fallback, exact-alias precedence, exact insufficient-history in both fact-status and calculation-payload forms alongside a valid legacy alias, closed-candle boundary equality, a higher-timeframe candle whose close_time exceeds the primary boundary despite preserved source open-time, higher-timeframe knowledge-time rejection, and S-01 price-versus-MA alignment when source open-time differs from indicator event boundary.

### 2.5 Second bounded correction from the independent re-audit

The second re-audit established that a non-valid exact EMA_20 can coexist with a valid numeric legacy EMA at the same event boundary. Alias comparison now occurs only when both the exact and legacy records are valid numeric calculations. If the exact alias is non-valid by its fact status or its calculation payload status, the resolver keeps that exact fact alone and surfaces its explicit non-valid state. The regression suite verifies that the legacy record is not included in the primary EMA finding's EvidenceRefs and that PRICE_VS_MA remains INSUFFICIENT_DATA rather than CONTRADICTORY.

The append-only integration evidence now verifies that the governed trigger exists and is enabled, checks the stable database denial semantics (trigger SQLSTATE P0001 with the canonical append-only message, or the explicit table-privilege denial SQLSTATE 42501 when the connection role is denied before trigger execution), and compares the complete persisted row before and after both UPDATE and DELETE attempts. Each attempt must be rejected; the row must remain present with unchanged identity, payload, evidence, reason/status and persistence metadata. No trigger, grant, or database protection is weakened.

## 3. S-01 — Technical behavior

S-01 emits deterministic findings for:

- MA_ALIGNMENT across configured EMA periods;
- PRICE_VS_MA using the closed-candle close and configured primary EMA;
- MACD_STATE from persisted MACD, signal and histogram;
- RSI_ZONE using configured oversold/overbought thresholds;
- ADX_STRENGTH using the configured ADX threshold;
- BOLLINGER_POSITION from close and persisted upper/middle/lower bands;
- BOLLINGER_SQUEEZE from persisted bandwidth and a configured inclusive threshold.

Components that must be compared are checked against the semantic event boundary: canonical close_time for price and persisted indicator event_time for indicator facts. Incomplete EMA coverage is exposed with per-period state/reason details. RSI/ADX domains, Bollinger ordering, negative bandwidth, boolean numeric values and non-finite values are not silently accepted. Divergence remains explicitly out of scope.

## 4. S-06 — Multi-Timeframe behavior

S-06 independently interprets each configured symbol/venue/timeframe using the closed-candle close, configured primary EMA, MACD, MACD signal and RSI. It does not consume S-01 output.

- BULLISH requires close above EMA, MACD above signal and RSI at/above the configured midline.
- BEARISH requires close below EMA, MACD below signal and RSI below the configured midline.
- NEUTRAL means valid aligned facts do not satisfy either directional conjunction.
- CONFLUENCE requires the required timeframes to establish the same bullish/bearish direction.
- CONFLICT identifies opposing directional timeframes.
- PARTIAL represents incomplete, neutral, contradictory or post-boundary coverage; each timeframe finding retains its explicit state.
- Missing required facts or insufficient higher-timeframe history remain INSUFFICIENT_DATA.

The primary closed-candle boundary and primary knowledge_time are retained separately. Source-row event_time remains the original candle open boundary in provenance. A future or post-boundary higher-timeframe fact is not admitted merely because it is already present in the Snapshot.

## 5. S-08 — Volatility behavior

S-08 uses only persisted ATR, historical volatility, ATR percentile, volatility expansion ratio and Bollinger bandwidth. It emits LOW / NORMAL / HIGH classification, EXPANDING / CONTRACTING / STABLE state, and HIGH_VOLATILITY risk flag where supported by the valid facts and configured boundaries. Missing or invalid components remain explicit. No new estimator or P4 calculation was introduced.
