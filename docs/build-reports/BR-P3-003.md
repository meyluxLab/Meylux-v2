- validates timestamp representation using the existing P3-001 UTC timestamp foundation;

## 5. Temporal / Sequence / Completeness Behavior

### Temporal

- existing aware UTC timestamp semantics are consumed;
- `event_time > received_at` is rejected;
- future-event checking is deterministic when an explicit `reference_time` is supplied;
- no implicit current-time or clock-skew policy is introduced;
- chronological ordering violations are rejected.

### Sequence

- source sequence remains an opaque contract field;
- exact duplicate sequence values are rejected within the provider/instrument stream;
- sequence continuity/order is checked only through an explicitly supplied authoritative successor function;
- no numeric interpretation is applied to opaque sequence values when no authoritative successor semantics exist.

### Completeness / Cadence

- cadence continuity is checked only when an explicit authoritative cadence function is supplied;
- missing sequence evidence is not fabricated or silently repaired;
- absent authoritative cadence/sequence semantics do not cause an invented gap policy;
- missing, invalid, contradictory, or incomplete evidence is preserved as validation findings rather than repaired.
