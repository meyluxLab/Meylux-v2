## 3. Regime semantics
The deterministic regime engine uses two directional factors in fixed order:
1. Trend factor: (current_close - mean(prior trend_lookback closes)) / mean(prior trend_lookback closes).
2. Momentum factor: (current_close - close[lookback]) / close[lookback].

Entry classification uses >= +entry_threshold for BULLISH and <= -entry_threshold for BEARISH. Values strictly between the exact boundaries are RANGE.

A candidate regime is BULLISH only when both factors are BULLISH; BEARISH only when both are BEARISH; all disagreement/neutral combinations resolve deterministically to RANGE.

For an existing BULLISH state, both factors must remain strictly above their configured exit thresholds to persist BULLISH. Exact equality at the exit threshold therefore exits the state. If both factors qualify the opposite direction, the transition is directly BEARISH; otherwise the state becomes RANGE.

The BEARISH rule is symmetric.

No hidden state or wall-clock timing participates in classification.

## 4. Hysteresis transition matrix
| Previous state | Current factor condition | Result |
|---|---|---|
| none | both bullish | BULLISH |
| none | both bearish | BEARISH |
| none | otherwise | RANGE |
| BULLISH | both values > exit | BULLISH |
| BULLISH | both opposite entry conditions | BEARISH |
| BULLISH | otherwise | RANGE |
| BEARISH | both values < -exit | BEARISH |

| BEARISH | otherwise | RANGE |
| RANGE | both bullish | BULLISH |
| RANGE | both bearish | BEARISH |
| RANGE | otherwise | RANGE |
| INSUFFICIENT | insufficient history | INSUFFICIENT |

The matrix is implemented directly in MarketRegimeEngine._apply_hysteresis() and covered by exact-boundary tests.

## 6. Venue-aware quantitative evidence semantics
VenueEvidenceEngine compares two provider-neutral VenueEvidence facts only when:
- both inputs are VALID;
- metric identity matches;
- canonical symbol/instrument identity matches;
- timeframe matches;
- both venue contexts exist and are different;
- timestamps are present and exactly aligned.

A compatible comparison returns COMPARABLE with exact right - left Decimal difference and composed venue/source provenance.

Instrument, timeframe, timestamp or metric mismatch returns INCOMPATIBLE with explicit INVALID_INPUT.

Missing venue context or non-valid evidence returns INSUFFICIENT_EVIDENCE.

Same-venue input is explicitly rejected as not being a cross-venue comparison.

No provider-specific wire field is introduced and no venue recommendation is generated.

## 7. Numeric / temporal / provenance integrity

When explicit context is absent, deterministic context is derived from canonical provenance IDs and observed candle metadata. Explicit caller context remains authoritative.
