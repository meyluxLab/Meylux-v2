## 2. Implementation delivered

### 2.1 S-10

Implemented S-10 as a deterministic reference specialist over the authoritative InputSnapshot.

The implementation:

- consumes only Snapshot facts;
- rechecks knowledge_time <= as_of;
- resolves every EvidenceRef against Snapshot provenance;
- checks evidence identity/record consistency;
- preserves UTC timestamp semantics;
- performs deterministic worst-status classification;
- explicitly represents STALE_INPUT, INCOMPLETE_HISTORY, CONTRADICTORY_INPUT, UNAVAILABLE_INPUT, INVALID_INPUT and PARTIAL_INPUT;
- rejects malformed canonical transport and semantic/contract violations without retry;
- enforces bounded finding/evidence cardinality;
- preserves stable output identity and canonical serialization;
- rejects lookahead rather than repairing it.

### 2.2 Queue / worker runtime

Reused the existing Redis Streams foundation and added the S-10 runtime boundary:

- FIFO enqueue/delivery policy;
- configuration-driven concurrency;
- configuration-driven timeout;
- bounded retry/backoff;
- overload/backpressure rejection;
- idempotency key;
- consumer-group stale recovery;
- deterministic retry transition;
- direct DLQ for explicit non-retryable semantic failures;
- DLQ after bounded transient retry exhaustion;
- explicit classification of transient persistence failures.

The queue foundation was restored after an intermediate implementation review so existing retry/recovery semantics were preserved.

### 2.3 Persistence

Specialist persistence remains append-only and uses the existing P5-001 table.

Insert result is now derived from PostgreSQL:

INSERT ... ON CONFLICT (identity_hash) DO NOTHING RETURNING record_id

This removes race-sensitive pre-check semantics. Duplicate replay therefore returns inserted=False, while the actual winner returns inserted=True. The worker then performs deterministic read-back by identity.

No UPDATE/DELETE path was introduced.

### 2.4 Runtime packaging

Added:

- worker-specialist Compose service;
- specialist configuration packaged into the runtime image;
- runtime service dispatch for worker-specialist;
- configuration version 1.1.0 with timeout, concurrency, retry, backlog, retention and output bounds.

The safety configuration remains read-only and explicitly disables private-provider access, trading, capital movement and custody.
