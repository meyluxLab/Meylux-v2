## 6A. AR-P4-007 Correction Cycle — F-01 and F-02

CONTROL identified two blocking defects: canonical provenance was not automatically propagated when explicit context was omitted, and ClosedBar used an inclusive end boundary that permitted duplicate trade ownership across adjacent CVD bars.

### F-01 correction

When explicit QuantitativeContext is omitted, the implementation now derives deterministic context directly from canonical evidence.

The derived context preserves, where the canonical inputs actually provide it:

- source_ref: ordered canonical provenance_id composition;
- timestamp: latest contributing canonical evidence timestamp;
- symbol: canonical instrument identity.

timeframe and venue_context remain unset when the canonical contracts do not provide those fields. No value is fabricated or inferred.

Multi-input lineage is composed deterministically in semantic input order, and repeated provenance identifiers are retained rather than silently discarded.

Direct regression coverage now exists for:

- Volume Profile provenance propagation;
- Bar Delta provenance propagation;
- cumulative CVD provenance propagation;
- Derivatives provenance propagation.

### F-02 correction

ClosedBar now uses the explicit half-open interval:

[start_time, end_time)

A trade exactly at end_time is therefore not owned by that bar and can be owned only by an adjacent bar beginning at that exact timestamp.

CVD continues to reject temporal overlap rather than sorting or repairing contradictory input.

CVD now also enforces one instrument across the complete non-empty bar sequence.

Direct regression coverage now demonstrates:

- end-boundary trade rejection by the first bar;
- acceptance by the adjacent next bar;
- valid adjacent same-instrument bars;
- no double counting across the shared boundary;
- cross-instrument CVD rejection.

No future-Step functionality or scope expansion was introduced.

## 6B. AR-P4-008 Correction Cycle — F-03 and F-04

CONTROL identified two new blockers during AR-P4-008: Bar Delta permitted cross-instrument aggregation, and this Build Report contained contradictory CI attribution for Run #875.

### F-03 correction

OrderFlowEngine.bar_delta() now rejects a non-empty trade sequence when any trade has an instrument_id different from the first validated trade.

The rejection occurs before Delta aggregation and before derived context is used as an instrument label. No trade is sorted, dropped, coerced, or silently repaired.

Direct regression coverage now demonstrates:

- valid same-instrument Bar Delta input remains VALID and retains the validated instrument in derived context;
- cross-instrument Bar Delta input raises ValueError and cannot produce an aggregated Delta.

## 7. Determinism and no-lookahead

Volume Profile uses only trades inside the explicitly supplied profile interval and does not inspect future trades outside that interval.

CVD requires explicitly ordered, closed bars and rejects temporal overlap/order violations.

Derivative velocity/acceleration use only explicit current/prior canonical observations and their actual UTC timestamps. Missing history is never replaced by zero.

Repeated execution of identical complete input/configuration produces equal immutable outputs.
