## 3. Quantitative Contract Foundation

A shared immutable CalculationResult establishes common quantitative result semantics:

- value: finite Decimal or explicit absence (None);
- status: VALID, INSUFFICIENT_HISTORY, INVALID_INPUT, or UNAVAILABLE;
- reason: required deterministic semantic reason;
- context: optional immutable provenance/context carrying source reference, UTC timestamp, timeframe, symbol, venue context and version.

Domain wrappers are provided for Indicator, Market Structure, Volume Profile, Order Flow and Regime. They are deliberately thin semantic boundaries and do not implement later engines.

No new project Stable ID was invented for these contracts. The roadmap explicitly forbids inventing a new SID at this stage; contract files are implementation artifacts within the authorized foundation boundary.

## 4. Numeric Policy

The implementation uses Decimal throughout P4-001 primitives. This is an implementation-level choice within the Task Order and is compatible with the existing P3 canonical contract rule that Decimal is authoritative and binary floating-point is rejected.

Explicit behavior:

- float and bool numeric inputs are rejected;
- non-finite Decimal values are rejected;
- no implicit rounding;
- explicit quantization uses ROUND_HALF_EVEN;
- canonical numeric serialization is plain decimal notation;
- golden comparison is exact, with no epsilon tolerance;
- standard deviation uses a deterministic high-precision local Decimal context;
- insufficient history never receives a fabricated numeric value.

The complete implementation-level policy is recorded in docs/quantitative/NUMERIC_POLICY_P4_001.md.
