## 3. Event semantic-to-persistence mapping

Individual rows are written to `meylux.market_structure_events` using the existing engine event identity.

| Persisted field | Source / treatment |
|---|---|
| `record_id`, `identity_hash` | Existing `StructuralEvent.identity`; no alternate P5 identity is created |
| `symbol`, `timeframe` | Validated `TimeframeStructuralFacts`; timeframe map key and all source candles must agree |
| `event_time` | `StructuralEvent.event_location` |
| `knowledge_time` | `StructuralEvent.knowledge_time`, derived by the existing engine from the confirming closed candle |
| `event_type` | Original engine event type, unchanged |
| `value_numeric` | Exact Decimal `level`, or NULL when the event has no numeric level |
| `version` | Existing orchestration configuration version |
| `calculation_version` | Existing engine semantic version |
| `source_ref` | `canonical-provenance:` plus the deterministic source-window provenance IDs; window selection follows the event's known candle dependencies |
| `venue_context` | Only the venue resolved through existing authoritative raw-acquisition provenance; remains NULL when that evidence does not establish one venue |
| `payload_json` | Event identity/type, event location, confirmation time, knowledge time, direction, level/bounds, lifecycle, structural state, prior state, source event identity, source/member identities, semantic version, source candle provenance, confirmation candle provenance, source-window provenance, and zone formation time |
| `persisted_at` | Existing database default only; never substituted for event/confirmation/knowledge time |

The persisted row keeps the event's temporal semantics distinct. The database `event_time` represents event location; `confirmation_time` remains explicit in the payload; `knowledge_time` is its own authoritative database column; and `persisted_at` remains the database persistence timestamp.

For confirmed facts, the ratified engine semantics establish `confirmation_time == knowledge_time`. The implementation validates UTC temporal values, rejects event locations after confirmation, and rejects any structural knowledge time later than the primary snapshot boundary.

## 4. Zone semantic-to-persistence mapping

Zone-bearing facts and lifecycle transitions are appended to `meylux.market_structure_zones`. The persisted `zone_type` is the stable zone family, while the original transition event type remains in the payload:

| Original engine event type | Persisted `zone_type` |
|---|---|
| `FVG`, `FVG_LIFECYCLE` | `FVG` |
| `ORDER_BLOCK`, `ORDER_BLOCK_INVALIDATION` | `ORDER_BLOCK` |
| `BREAKER`, `BREAKER_INVALIDATION` | `BREAKER` |
| `LIQUIDITY_POOL`, `LIQUIDITY_POOL_SWEEP` | `LIQUIDITY_POOL` |

Zone payloads preserve the original event type, bounds, direction, lifecycle, source event identity, source/member identities, provenance, venue context, semantic version, and `zone_formation_time`. For a lifecycle transition, the source event must resolve to an event in the same authoritative analysis; otherwise persistence fails closed. The transition's `event_time` is its event location, while `zone_formation_time` preserves the original zone formation location. A lifecycle transition creates a new immutable row; no historical zone row is updated or deleted.

Zone rows are emitted only for the existing engine's zone-bearing event families and applicable bounds/pool-level facts. No new zone definition or market-structure mathematics is introduced.
