## 1. Outcome

The existing ratified `MarketStructureEngine` output now travels through the existing quantitative orchestration and persistence path as individual structural-event facts and append-only zone/lifecycle facts. The implementation does not create a second calculator or reinterpret P4 structural mathematics.

The existing `ORCHESTRATION` summary row remains for compatibility. It remains a summary rather than an individual `StructuralEvent`, and no authoritative fact-level `knowledge_time` is assigned to that summary.

No migration was added. Existing `knowledge_time` columns and append-only controls are reused. Individual structural facts persist the engine's authoritative `knowledge_time), distinct from `event_time` and database `persisted_at`.

### Correction outcome

CONTROL identified one blocking semantic defect: HH/HL/LH/LL classification event identity did not include the preceding same-side confirmed swing identity even though `DOC-P4-002 §15` requires source structural identity where applicable.

The bounded correction is now implemented:

- HH/LH classification events pass the preceding confirmed Swing High identity into the existing `_event(..., source=...)` identity material.
- HL/LL classification events pass the preceding confirmed Swing Low identity into the existing `_event(..., source=...)` identity material.
- The deterministic serialization and SHA-256 identity mechanism itself is unchanged.
- The existing P4 semantic version remains unchanged.
- Pinned golden expected classification identities were updated to the resulting deterministic identities.
- Pinned golden expected `source_event_identity` values were updated to the exact preceding same-side swing identities.
- Persistence retains both the classification's own identity and its preceding same-side swing identity as source/member identities.
- Other source-linked event families retain their existing source-member semantics; the current-member prepend is scoped only to HH/HL/LH/LL.

No new semantic rule, market-structure mathematics, contract, Stable ID convention, migration, or P5 implementation was introduced.

## 3. Event semantic-to-persistence mapping

Individual rows are written to `meylux.market_structure_events) using the existing engine event identity.

| Persisted field | Source / treatment |
|---|---|
| `record_id`, `identity_hash` | Existing `StructuralEvent.identity`; no alternate P5 identity |
| `symbol`, `timeframe` | Validated `TimeframeStructuralFacts`; source candles must agree |
| `event_time` | `StructuralEvent.event_location` |
| `knowledge_time` | `StructuralEvent.knowledge_time`, derived from the confirming closed candle |
| `event_type` | Original engine event type |
| `value_numeric` | Exact Decimal level, or NULL where no numeric level exists |
| `version` | Existing orchestration configuration version |
| `calculation_version` | Existing P4 engine semantic version |
| `source_ref` | Deterministic source-window provenance |
| `venue_context` | Only an authoritative resolved venue; otherwise NULL |
| `payload_json` | Event identity/type, timing, direction, bounds, lifecycle/state, source identities, provenance and semantic version |
| `persisted_at` | Database persistence timestamp only; never substituted for knowledge time |

Temporal semantics remain distinct: event location is `event_time); confirmation remains explicit in the payload; authoritative knowledge time is stored separately; persisted-at time is not used as market knowledge.

## 5. Timeframe, history, and no-lookahead treatment

- `QuantitativeOrchestrator.process()` delegates structure calculation to the existing `MarketStructureEngine`.
- Primary and eligible higher timeframes have independent `TimeframeStructuralFacts`.
- Structural facts require closed, strictly ordered canonical candles with consistent symbol/timeframe and UTC temporal values.
- Structural `knowledge_time` cannot exceed its timeframe boundary or the primary snapshot boundary.
- Higher-timeframe input closing after the primary knowledge boundary is rejected; exact boundary equality is eligible.
- Canonical gaps are not repaired. Existing `UNCONFIRMED) and insufficient-history behavior remains explicit.
- No synthetic market data is introduced by implementation code.
- Replay uses the same closed-candle input and deterministic engine; it does not manufacture fallback facts.

## 6. Source-sensitive identity, provenance, and replay

### Classification identity correction

For each classification event:

- HH/LH source = immediately preceding confirmed same-side `SWING_HIGH) identity.
- HL/LL source = immediately preceding confirmed same-side `SWING_LOW) identity.
- The source identity is included in the existing `_event()` deterministic hash material.
- `source_event_identity` on the resulting event equals that preceding same-side swing identity.
- Persistence records `(classification identity, preceding swing identity)` as source/member identities.
- The persistence prepend is explicitly limited to HH/HL/LH/LL so FVG, Order Block, Breaker and other source-linked facts retain their established member semantics.
