## Implemented Mapping Coverage

### Binance

- instrument identity and spot semantics
- stream candle mapping including explicit timeframe
- trade mapping including price, quantity, timestamp, trade id and supported buyer-maker side translation
- order-book snapshot mapping
- provenance preservation

### MEXC

- instrument identity and spot semantics where explicit instrument metadata is supplied
- protobuf candle mapping with explicit interval and seconds-based window timestamps
- trade mapping with explicit price, quantity, timestamp and trade id
- order-book list mapping
- provenance preservation

### Canonical safety boundary

- existing canonical contract constructors are reused
- `AcquisitionEnvelope` identity authority is preserved
- binary floating-point market values are not introduced by the normalization layer
- malformed or unsupported mappings return explicit rejected outcomes
- non-AVAILABLE acquisition evidence is never promoted to canonical truth
- provider-only fields are not copied into canonical objects
- ambiguous MEXC `tradeType` is intentionally not interpreted without authoritative semantics
- derivatives mapping is accepted only when canonical field names are explicitly present; unsupported provider aliases are rejected rather than guessed
- Binance/MEXC spot market and contract semantics are limited to the provider adapters authorized by this Task Order

## Deviations / Open Questions

1. Binance REST kline rows do not carry the requested timeframe in the validated acquisition envelope payload; P3-005 therefore requires explicit timeframe-bearing candle input rather than inventing timeframe context.
2. MEXC `tradeType` semantics were not promoted into canonical aggressor side because the available authoritative implementation evidence does not establish its meaning. An explicit `isBuyerMaker` boolean is accepted if supplied.
3. Provider-specific derivatives aliases are not guessed. Only explicitly canonical derivative field names are mapped in this implementation boundary.

These are implementation-boundary decisions, not architecture changes.
