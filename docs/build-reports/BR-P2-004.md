## Implementation details

### Migration integration

The governed migration path remains the existing `infrastructure/postgres/migrate.sh`; it now executes migration `0001_database_foundation.sql` followed by `0002_raw_acquisition_staging.sql`. No new migration framework was introduced.

### Persistence failure recovery

`AcquisitionCollector` uses a bounded `max_persistence_retries` policy. A failed persistence operation is retried synchronously up to the configured bound. If all attempts fail, the exact `AcquisitionEnvelope` is retained in a bounded recovery buffer and exposed for explicit replay through `replay_recovery()`. Recovery capacity exhaustion raises an explicit `PersistenceRecoveryOverflow` instead of silently dropping evidence.

### Provider and sequencing coverage

Tests verify both Binance and MEXC traverse the same provider-neutral collector boundary, that existing adapter controls (`max_messages`, `max_reconnects`) are forwarded unchanged, and that source sequence values are preserved unchanged through collection. Provider stream failure is isolated from the other configured provider.

### State handling

The existing `CTR-P2-001` contract remains authoritative. Malformed acquisition state is rejected at the contract boundary; valid non-AVAILABLE states carrying their required provider error remain persistable as raw acquisition evidence. No Phase 3 normalization was introduced.

### CI foundation correction

The Docker Foundation workflow failure at `Run foundation self-checks` was investigated against the workflow definition. The self-check command lacked `PYTHONPATH=src`, while CI Core explicitly supplies that environment. The correction aligns the Docker Foundation self-check environment with the existing repository foundation convention. No infrastructure redesign was introduced.

The Docker workflow also validates the P2-004 migration record and `meylux.raw_acquisition_events` schema after running the existing migration harness.
