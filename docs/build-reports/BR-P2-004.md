### 2. Persistence failure recovery and lifecycle

`AcquisitionCollector` uses bounded persistence retries. Exhausted retries are retained in the bounded recovery buffer for explicit replay. Recovery-capacity exhaustion now enters a terminal bounded drain mode rather than terminating the consumer while queued work remains outstanding.

The current event is retained in an explicit overflow handoff, queued envelopes are drained and retained rather than silently discarded, provider production stops after terminal handoff, and `collect_once()` waits for queue completion before raising an explicit `PersistenceRecoveryOverflow` containing the unresolved evidence. Shutdown sentinels are only inserted for consumers that are still alive, preventing residual queue entries or shutdown hangs.

### 5. CI Docker Foundation failure investigation

The exact Run #35 execution log was inspected. The failure was not guessed.

`Run database migration harness` failed because the workflow's readiness probe used `pg_isready` against the default PostgreSQL Unix socket. The probe therefore returned success while the migration harness, which uses TCP `localhost`, immediately received `connection refused` on `127.0.0.1:5432`.

The repository correction changes the Docker Foundation readiness probe to explicitly test TCP readiness using `-h 127.0.0.1`, without changing the governed migration architecture or `migrate.sh` connection contract.

The same Run #35 log also confirms that before this correction:

- Compose validation passed;

- foundation self-checks passed (`Ran 104 tests ... OK`);
- database startup passed;
- database readiness through the Unix-socket probe passed;
- migration harness failed at TCP connection establishment.
