## 4. Contract Semantics Implemented

### Provider and instrument identity

`ProviderIdentity` separates provider identity from adapter identity/version. `InstrumentIdentity` carries both the canonical V2 instrument identity and the provider-side instrument identifier without embedding Binance/MEXC-specific behavior.

### Provenance

`Provenance` binds a provenance identifier to the exact provider identity and acquisition method. An envelope whose provenance references a different provider is rejected.

### Acquisition state

The contract explicitly represents:

- `AVAILABLE`
- `DEGRADED`
- `UNAVAILABLE`
- `STALE`
- `INVALID`
- `DISCONNECTED`
- `RATE_LIMITED`
- `SEQUENCE_GAP`
- `INSUFFICIENT_DATA`

Degraded/failure states require structured `ProviderError`; an `AVAILABLE` envelope cannot carry a provider error. This prevents synthetic success states and preserves missing/unreliable acquisition conditions explicitly.

### Capability and provider errors

`ProviderCapability` separates capability state from acquisition state. `ProviderError` provides stable code/category/message/retryable semantics without carrying provider-specific wire schema into the canonical contract.

### Time and sequence semantics

`event_time` and `received_at` must be timezone-aware UTC datetimes. `source_sequence` is optional because sequence semantics are provider/event dependent and are not assumed where unavailable.

Receive time is intentionally excluded from replay/deduplication identity because a replay can be received at a different wall-clock time.

### Deterministic serialization

The envelope is recursively immutable. Canonical serialization uses sorted JSON keys and compact separators. Decimal values are represented as exact strings; binary floating-point values and non-finite Decimal values are rejected.

### Replay / deduplication identity

`event_id` and `deduplication_key` are the SHA-256 digest of deterministic provider/instrument/event/time/sequence/payload identity material. Receive time, provider error detail, and capability state do not alter this identity. Provider identity remains part of the identity so independent provider streams cannot silently collide.

### Phase 2 → Phase 3 boundary

The envelope is a raw/staging acquisition representation. It does not normalize provider values into canonical analytical truth and does not take ownership of Phase 3 Validation / Normalization / Data Quality behavior.

## 10. Known Design Considerations

- Source sequence is represented as an opaque provider-neutral string. Later provider adapters must map provider sequence semantics into this field without redefining canonical contract identity.
- `event_id` intentionally includes payload in addition to source sequence. This protects same-timestamp collisions when a trustworthy source sequence is absent, while allowing receive-time changes during replay.
- Provider-specific wire schemas, retry algorithms, transport implementations, and live-stream lifecycle behavior remain outside this Step and belong to later provider/collector Steps.
