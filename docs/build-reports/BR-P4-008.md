## 3. Implementation

Changed implementation:
- src/meylux/acquisition/binance.py

The existing fetch_klines(symbol, interval, limit) boundary now:
1. validates the Binance provider-specific interval against the supported Binance Spot kline interval set;
2. preserves the caller/provider interval exactly, including 15m, 1h, and 4h;
3. preserves the original REST wire row under payload[row];
4. adds a provider-boundary payload[k] mapping containing the existing Binance kline fields plus explicit timeframe identity at payload[k][i];
5. derives payload[k][x] from the actual Binance kline close boundary relative to the adapter's UTC receipt clock, rather than assuming every REST candle is closed;
6. preserves the existing source_sequence as the Binance kline open-time value;
7. preserves existing provenance/provider/instrument/event semantics;
8. leaves AcquisitionEnvelope, CanonicalCandle, and P3 normalization contracts unchanged.

The additive k mapping is provider-boundary data shaping required by the already-existing P3 Binance mapping. It does not create a second timeframe contract.
