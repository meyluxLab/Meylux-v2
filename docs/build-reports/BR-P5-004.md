## 1. Objective and root cause

The P3 quality-evidence contract previously resolved timeframe only from payload-root `timeframe` and `interval`. Binance candle acquisition envelopes carry the authoritative interval under `payload["k"]["i"]`. As a result, the interval was dropped before deterministic quality-evidence identity and persistence, so the persisted EvidenceRef could not provide the timeframe required by the P5 Snapshot boundary.

The existing venue resolver correctly did not fall back to `provider_id`, but the Binance candle envelope did not expose an explicit venue context. The corrective implementation therefore keeps the two semantics separate: the Binance adapter adds explicit `venue: "BINANCE"` to candle envelopes as source-scoped context for Binance Spot candle endpoints, while the provider-neutral quality-evidence contract only reads explicit venue context and never infers venue from provider identity.

## 2. Implementation delivered

### 2.1 Provider-neutral timeframe extraction

`contracts/quality_evidence.py` now resolves explicit root `timeframe` / `interval` values and nested `k.i` together. All supplied values must be non-empty strings and must agree. A malformed `k` shape or malformed nested interval raises a validation error instead of silently omitting or fabricating context. If no authoritative timeframe is present, the value remains unavailable (`None`).

### 2.2 Explicit Binance candle venue context

`src/meylux/acquisition/binance.py` now preserves the authoritative nested interval and includes explicit venue context for Binance Spot REST klines and Binance Spot WebSocket kline events. This is adapter-scoped source context; the quality-evidence layer has no provider-id-to-venue fallback. Non-kline stream events are unchanged.

### 2.3 Persistence and P5 boundary

The existing append-only quality-evidence persistence schema already stores `timeframe` and `venue`, enforces `knowledge_time = received_at`, and maps persisted rows into the structured EvidenceRef. No migration was required and migration 0008 was not modified. Existing EvidenceRef, Snapshot, S-10 and specialist persistence contracts were not weakened or changed.

## 4. Semantic and failure behavior

- Root timeframe and nested `k.i` are accepted only when all supplied values agree.
- Missing timeframe remains unavailable; it is not inferred from symbol, event type, provider identity, receipt time, or persisted time.
- A non-object `k`, numeric interval, blank interval, or contradictory explicit interval is rejected.
- Venue remains absent when no explicit venue evidence exists; provider identity is not a fallback.
- Binance Spot candle adapter envelopes now carry explicit source-scoped venue context; provider identity remains `binance`.
- `knowledge_time` remains exactly `received_at`; event time and persistence time remain separate.
- Evidence identity remains deterministic and includes the resolved semantic context.
- Existing INSERT-on-conflict append-only persistence and contradiction detection are retained.
- Existing Snapshot lookahead checks and S-10 EvidenceRef identity checks are retained.
- No schema migration or frozen architecture change was introduced.
