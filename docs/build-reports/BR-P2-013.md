## 3. Implementation

### `src/meylux/acquisition/mexc_orderbook.py`

Added `MEXCOrderBookReconstructor` with deterministic state handling.

### Snapshot bootstrap

- Requires an AVAILABLE MEXC ORDER_BOOK envelope.
- Requires a non-negative decimal `lastUpdateId`.
- Validates snapshot bid/ask structures, exact Decimal-compatible values, positive prices and quantities.
- Rejects empty books, duplicate prices and crossed books.
- Validates provider instrument identity.
- Preserves snapshot event identity and provenance.
- Produces an existing `CanonicalOrderBook` only after all predicates pass.

### Version handling

- `fromVersion` and `toVersion` are parsed as integer version evidence only.
- Boolean, floating-point, malformed, negative and non-numeric version values are rejected.
- `fromVersion > toVersion` is rejected.
- No version value is promoted into canonical identity or canonical payload.

### Continuity

For established state `V_prev`:

- exact `fromVersion == V_prev + 1` is accepted;
- an initial snapshot-boundary update may overlap the snapshot version when the update spans the required next version;
- a later unsupported overlap causes recovery rather than silent acceptance;
- `fromVersion > V_prev + 1` creates a continuity gap and hides the previous state from canonicalization;
- `toVersion <= V_prev` is treated as stale/duplicate and cannot regress state.

### Absolute depth reconstruction

- Provider depth quantities are treated as absolute quantities.
- Positive quantity replaces the level.
- Zero quantity removes the level.
- Final reconstructed state is deterministically sorted.
- Crossed, empty or otherwise invalid reconstructed books are rejected and routed to recovery.

### Recovery

`apply_depth_with_recovery()`:

1. detects a recovery-required condition;
2. invalidates current canonical eligibility;
3. invokes the supplied REST snapshot loader;
4. accepts the new snapshot only if independently valid;
5. returns `RECOVERED` on successful re-bootstrap;
6. returns explicit `UNAVAILABLE`/`INVALID` outcomes on recovery failure;
7. records recovery-attempt count;
8. never fabricates a replacement order book.

### Disconnect/restart

- A disconnected stream requires recovery.
- A reconstructor with no snapshot state cannot expose an authoritative canonical book.
- Recovery failures do not leave stale state canonically visible.

### Provenance/replay

- Existing `AcquisitionEnvelope.event_id` identity remains authoritative for raw evidence.
- Accepted evidence event IDs are retained in a bounded deterministic chain.
- Canonical provenance remains the existing provider provenance ID.
- Identical acquisition evidence remains deterministically replayable.
- No historical canonical rewrite or persistence migration was introduced.
