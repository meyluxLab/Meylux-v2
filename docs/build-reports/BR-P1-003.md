## 3. Database Foundation

The foundation establishes:

- TimescaleDB extension.
- `meylux` schema owned by `meylux_admin`.
- `meylux.schema_migrations` bookkeeping table.
- `meylux_admin` as the database foundation administration/ownership role through the Compose bootstrap boundary.
- `meylux_app` as the bounded application role.
- `meylux_backup` as the bounded backup/read role.

The migration is idempotent for extension, schema, role creation, and migration-record insertion.

## 4. Privilege Boundary

`meylux_app` receives SELECT/INSERT/UPDATE privileges on foundation tables, but cannot DELETE or TRUNCATE them. On `meylux.schema_migrations`, application INSERT and UPDATE are explicitly revoked so migration state remains controlled by the administrative boundary.

`meylux_backup` receives SELECT-only access to the foundation schema tables.

Role passwords are supplied only through environment variables consumed by the migration harness. No password value is persisted in repository artifacts.

## 5. Deterministic Database Configuration

The migration executes with UTC session time and applies UTC as the database timezone configuration.

`config/database.py` exposes only explicit configuration values and performs no filesystem, network, wall-clock, or database access at import time.

The migration harness uses `set -euo pipefail` and PostgreSQL `ON_ERROR_STOP=1` so migration failures are surfaced rather than silently continued.
