## 1. Scope

Implemented the Binance provider adapter within the established `CMP-P2-001` / `CTR-P2-001` provider-neutral acquisition boundary. No MEXC implementation, collector/persistence work, Phase 3 normalization, Phase 4 computation, production deployment, or trading/capital activity was performed.

The adapter provides:

- Binance spot REST/bootstrap acquisition for exchange information, order-book snapshots, trades, and klines;
- Binance combined live market-stream acquisition and provider-neutral event mapping;
- bounded REST retry and bounded WebSocket reconnect behavior;
- provider identity, instrument identity, provenance, event time, receive time, source sequence, state, and deterministic envelope construction;
- integration with the existing structured observability foundation when a logger is supplied;
- no credential or authentication-material handling for the public market-data scope.

## 5. REST / Bootstrap Implementation

Implemented:

- `fetch_exchange_info()`;
- `fetch_order_book()`;
- `fetch_trades()`;
- `fetch_klines()`;
- `bootstrap()` combining exchange metadata and order-book acquisition.

Provider payloads remain raw/staging acquisition payloads. No Phase 3 validation or normalization is performed.

## 6. Live Stream Implementation

Implemented an asynchronous combined-stream adapter with:

- symbol normalization;
- bounded stream count validation;
- trade, aggregate-trade, depth-update, kline, and book-ticker mapping;
- provider source sequence extraction where available;
- combined-stream envelope unwrapping;
- explicit message-count stop capability for bounded validation;
- bounded reconnect count and bounded reconnect delay.

No user-data/account stream, order stream, or authenticated Binance capability was implemented.

## 7. Retry / Reconnect Boundary

REST retries are bounded by `RetryPolicy.max_attempts`, with capped exponential delay.

WebSocket reconnects are bounded by `max_reconnects` for one `stream()` invocation. The implementation does not create an uncontrolled infinite reconnect loop within a single invocation.

## 8. Provider Isolation

The adapter keeps Binance-specific URLs, stream names, wire parsing, and transport behavior inside `src/meylux/acquisition/binance.py`. It does not mutate MEXC state, shared provider state, canonical persistence, or Phase 3 validation state.

Each adapter instance owns its transport configuration and has no mutable module-level provider state.

## 9. Telemetry

The adapter can emit structured events through the existing `meylux.observability` `emit()` mechanism for bootstrap, REST retry, stream connect/disconnect/error/cancel/stop events.

No credentials, API keys, cookies, authorization headers, or private authentication material are accepted by the public market-data adapter and none were written to repository artifacts.
