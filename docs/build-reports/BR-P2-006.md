## 6. MEXC — Live WebSocket Evidence and Blocking Finding

A bounded live MEXC WebSocket acquisition was attempted through the existing `MEXCAdapter`.

Actual adapter result:

```text
MEXC_STREAM_STATE=INVALID
MEXC_STREAM_EVENT_TYPE=UPDATE
MEXC_STREAM_PROVIDER=mexc
MEXC_STREAM_ERROR_CODE=MEXC_INVALID_STREAM_PAYLOAD
MEXC_STREAM_ERROR_CATEGORY=INVALID_PAYLOAD
MEXC_STREAM_ERROR_MESSAGE=MEXC market-data stream payload must be protobuf bytes
MEXC_STREAM_RETRYABLE=False
```

The Producer then independently inspected the actual wire sequence without changing the adapter implementation.

Actual MEXC wire evidence:

```text
MEXC_RAW_1_TYPE=str
MEXC_RAW_1_MESSAGE={"id":0,"code":0,"msg":"spot@public.aggre.deals.v3.api.pb@100ms@BTCUSDT"}
MEXC_RAW_2_TYPE=bytes
MEXC_RAW_2_BYTES_LEN=338
```

The first server message is a JSON subscription acknowledgement. The second message is actual protobuf market-data bytes.

The existing MEXC parser was separately exercised against the actual protobuf market-data bytes received from the live provider:

```text
MEXC_MARKET_TYPE=bytes
MEXC_MARKET_BYTES_LEN=338
MEXC_PROTOBUF_PARSE_STATE=AVAILABLE
MEXC_PROTOBUF_PARSE_EVENT_TYPE=TRADE
MEXC_PROTOBUF_PARSE_PROVIDER=mexc
MEXC_PROTOBUF_PARSE_SEQUENCE=727194192953987076X0_727194192953987077X0
```

### Material Verification Finding

The existing `MEXCAdapter.stream()` path currently passes the initial JSON subscription acknowledgement to `parse_stream_message()`, while `parse_stream_message()` rejects non-control JSON market-stream messages as `MEXC_INVALID_STREAM_PAYLOAD`.

Consequently, the live MEXC stream path terminates on the subscription acknowledgement before the subsequent protobuf market-data message can be consumed by the adapter's normal stream loop.

This is a material P2-006 verification finding affecting the existing MEXC live acquisition path.

**No implementation correction was made.**

Per `TO-P2-006`, the affected verification part is stopped and the finding is reported to CONTROL rather than silently changing the governed implementation.

The Producer therefore does not claim MEXC live-stream end-to-end PASS.

### D-P2-006-001 — MEXC Live WebSocket Subscription-Acknowledgement Handling

The existing MEXC adapter rejects the live JSON subscription acknowledgement before consuming the subsequent protobuf market-data message.

This prevents a clean end-to-end MEXC WebSocket PASS through the governed adapter path.

No code correction was made because the authorized Task Order requires the verification finding to be reported rather than silently changing implementation behavior.
