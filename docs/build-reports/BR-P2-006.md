The existing MEXC parser was separately exercised against the actual protobuf market-data bytes received from the live provider:

```text

MEXC_PROTOBUF_PARSE_STATE=AVAILABLE

MEXC_PROTOBUF_PARSE_PROVIDER=mexc
MEXC_PROTOBUF_PARSE_SEQUENCE=727194192953987076X0_727194192953987077X0
```

### Material Verification Finding

The existing `MEXCAdapter.stream()` path currently passes the initial JSON subscription acknowledgement to `parse_stream_message()`, while `parse_stream_message()` rejects non-control JSON market-stream messages as `MEXC_INVALID_STREAM_PAYLOAD`.

Consequently, the live MEXC stream path terminates on the subscription acknowledgement before the subsequent protobuf market-data message can be consumed by the adapter's normal stream loop.

This is a material P2-006 verification finding affecting the existing MEXC live acquisition path.

**No implementation correction was made.**

Per `TO-P2-006`, the affected verification part is stopped and the finding is reported to CONTROL rather than silently changing the governed implementation.

The Producer therefore does not claim MEXC live-stream end-to-end PASS.

Changed implementation path:

`src/meylux/acquisition/mexc.py`

The existing stream loop therefore continues to the next WebSocket frame. Actual protobuf market-data bytes remain processed by the unchanged existing protobuf parser.

No acknowledgement is converted into an acquisition event.

No unrelated malformed JSON or non-success control response is accepted as market data.
