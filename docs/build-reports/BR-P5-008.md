## 5. Canonical Snapshot JSON transport defect and correction

During the first real Docker integration execution, S-17 reached the semantic-error/DLQ path.

The defect was in the transport boundary rather than in the underlying P4 Volume Profile facts. In-memory snapshots represented candle `close_time` as a UTC datetime, while canonical Snapshot JSON transport reconstructed the same value as an ISO-8601 string. One S-17 comparison path passed the transported string directly into strict UTC-datetime validation.

Producer corrected this by introducing the internal `_candle_close_time()` normalization helper in `src/meylux/specialists/group_c.py`. The helper accepts the canonical string/datetime representation, parses ISO-8601 values, normalizes them to UTC, and is used by the S-17 candle close-time comparisons.

This is a real transport-semantics correction. It does not weaken validation, bypass the queue path, or change the authoritative contract.

A dedicated regression was added:

`test_s17_survives_canonical_snapshot_json_transport`

The regression reconstructs the snapshot through canonical serialization/transport and verifies that S-17 still produces the expected position finding.

Temporary diagnostic preflight instrumentation added during root-cause isolation was removed after the defect was corrected. The final integration test therefore exercises the actual queue/worker/specialist/persistence path rather than a diagnostic shortcut.
