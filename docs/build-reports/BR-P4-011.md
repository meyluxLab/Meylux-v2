## 1. Outcome

The existing deterministic P4 indicator functions are now composed into a complete Group-A fact surface and emitted independently for the primary timeframe and each supplied, eligible higher timeframe. The existing append-only P4 persistence boundary is retained. The implementation does not introduce new indicator mathematics, a competing truth store, a migration, a P5 recomputation path, or a change to the established `knowledge_time` rule.

For each orchestration call, the persisted surface contains the latest eligible closed-candle fact for each available timeframe. A supplied higher-timeframe sequence is validated in full before its latest eligible fact set is calculated. Every persisted indicator fact is individually named in its JSON payload, carries its deterministic calculation result and provenance context, and is keyed by deterministic identity.

## 2. Implemented fact families

The existing quantitative library functions are reused directly:

- `EMA` through the existing configured EMA period.
- `RSI` with the existing default period of 14.
- `MACD`, `MACD_SIGNAL`, and `MACD_HISTOGRAM` with 12/26/9 defaults.
- `ATR` and `ADX` with 14-period defaults.
- `BOLLINGER_MIDDLE`, `BOLLINGER_UPPER`, `BOLLINGER_LOWER`, and `BOLLINGER_BANDWIDTH` using the existing Bollinger implementation with 20/2 defaults.
- `HISTORICAL_VOLATILITY` using the existing implementation and its existing 365-period annualization default.
- `ATR_PERCENTILE` using the existing ATR percentile implementation and a 100-observation lookback default.
- `VOLATILITY_EXPANSION_RATIO` using the existing implementation and a 20-observation baseline-window default.

These configuration defaults are explicit in `QuantOrchestrationConfig`. The existing EMA/RSI/ATR settings and version remain backward-compatible in constructor position. The implementation does not modify the underlying indicator algorithms or golden vectors. The bandwidth result is given a provenance context only if the existing bandwidth function omitted one; its numeric value, status, and reason remain unchanged.

## 3. MTF, no-lookahead, and temporal boundary

The orchestration path now calculates the same fact families independently for each supplied higher timeframe after validating:

- the candle objects and closed-candle state;
- a consistent instrument and timeframe per series;
- strictly increasing open times and non-overlapping intervals;
- matching higher-timeframe map keys and candle timeframe values;
- that the supplied higher timeframe differs from the primary timeframe; and
- that no supplied higher-timeframe candle closes after the primary candle's knowledge boundary.

The implementation rejects post-boundary higher-timeframe input rather than silently truncating the sequence. A candle closing exactly at the primary knowledge boundary remains eligible. A higher-timeframe fact uses its own closed candle's `close_time` as `event_time` and `knowledge_time`; persistence verifies that this knowledge time does not exceed the primary boundary.

The existing `MTFAlignment.timeframe` meaning and regime payload shape are preserved to avoid an unrelated identity change in regime snapshots.

## 4. Persistence, identity, and provenance

All indicator facts use the existing `meylux.calculated_indicator_vectors` table and its existing `event_time`-derived `knowledge_time` from migration `0008_p4_knowledge_time_persistence.sql`. No new table, migration, generated-column change, historical backfill, UPDATE, or DELETE was introduced.

The existing table has no dedicated indicator-name column. To make the persisted fact family unambiguously discoverable through the existing read-back path, each newly written indicator payload now includes `fact_name` alongside the calculation's `value`, `status`, `reason`, and `context`. The fact name participates in the deterministic identity material. The context preserves source reference, event timestamp, timeframe, instrument, and calculation-context version. This is additive payload metadata, not a new storage boundary.

Existing historical rows are not rewritten or backfilled. Rows created before this implementation may not contain `fact_name`; the new payload contract applies to newly emitted Group-A facts.

The existing read-back method remains the query surface and filters by both symbol and timeframe. Parameterized optional time bounds retain deterministic placeholder ordering.

## 5. Replay, insufficiency, and malformed inputs

The same calculation and identity path is used on replay. Inserts remain `ON CONFLICT(identity_hash) DO NOTHING`; repeated persistence of the same primary/MTF result inserts no duplicate rows. Higher-timeframe identity includes the timeframe and its event boundary, so primary and higher-timeframe facts remain independent even when their candle close timestamps coincide.

Insufficient history is represented using the existing calculation statuses, reason values, and `null` numeric values. No historical values are synthesized. The tests cover short histories, invalid MACD period relationships, non-finite decimal serialization, incomplete candles, mixed instruments, mismatched timeframe keys, and future higher-timeframe candles. Primary candle ordering and interval overlap are also validated.
