## 4. Quality Semantics Actually Implemented

Record-level states:
`VALID`, `DEGRADED`, `STALE`, `INCOMPLETE`, `CONTRADICTORY`, `REJECTED`, `UNAVAILABLE`.

Pipeline lifecycle mapping used by the implementation:
- `VALID` → `CANONICAL`
- `DEGRADED` → `QUALITY_DEGRADED`
- `STALE` → `QUALITY_DEGRADED`
- `INCOMPLETE`, `CONTRADICTORY`, `REJECTED`, `UNAVAILABLE` → `REJECTED`

Canonical eligibility is granted only to `VALID` evidence with explicit provenance and lineage identifiers.

## 5. Score Semantics

The explanation vector contains, in fixed order:

`freshness`, `completeness`, `consistency`, `feed_health`, `validation_status`, `provider_capability`.

Each supplied component must be an exact finite `Decimal` within `0.00–1.00`.

A score is emitted only when all six components are present and is the deterministic arithmetic mean quantized to two decimal places.

If any component is absent, score is `None`; no substitute is fabricated.

## 6. Quarantine / DLQ

Invalid/non-promotable evidence is converted into an evidence-bearing `QuarantineRecord`.

The record contains:
- deterministic deduplication key;
- quality state;
- deterministically ordered reason codes;
- available provenance;
- available source/lineage references;
- deterministic payload fingerprint;
- retry attempt.

`BoundedQuarantine` enforces a finite capacity. Duplicate retries are idempotent. Capacity exhaustion raises an explicit `OverflowError` and does not silently discard or promote the input.

Degraded and stale evidence remain explicit `QUALITY_DEGRADED` outcomes rather than being automatically placed into the DLQ.

## 7. Lineage / Provenance

Canonical-eligible and routed records preserve existing provenance references. No upstream identifier is fabricated.

For canonical eligibility, provenance, source record identity and lineage parent identity are mandatory. Missing lineage converts an otherwise valid candidate to explicit `INCOMPLETE` and blocks canonical promotion.

## 14. CONTROL Correction Cycle — Re-audit Evidence

CONTROL identified two substantive findings. Both were corrected strictly within TO-P3-007 Revision 1.1.

### Finding 1 — Deterministic precedence

The corrected precedence is:

1. record_available == False → UNAVAILABLE.
2. Missing validation outcome → INCOMPLETE.
3. Explicit validation outcomes CONTRADICTORY, REJECTED, INCOMPLETE, and UNAVAILABLE are safety-dominant and cannot be weakened by CapabilityState.DEGRADED.
4. For an otherwise valid/degradable validation result, UNSUPPORTED/UNAVAILABLE capability maps to UNAVAILABLE.
5. CapabilityState.DEGRADED may classify otherwise-valid evidence as DEGRADED, but cannot override stronger validation evidence.
6. Explicit validation STALE and DEGRADED remain their governed states.

This makes conflicting evidence classification deterministic and prevents rejected/incomplete/contradictory validation evidence from being downgraded merely because capability is degraded.

### Finding 2 — Partial quarantine evidence

QualityAssessment now independently preserves provenance_id, source_record_id, and lineage_parent_id.

QualityLineage remains a complete canonical-lineage object and is created only when all required lineage references exist.

Quarantine records no longer depend on complete QualityLineage to retain available upstream evidence. Missing references remain None; no identifier is fabricated.
