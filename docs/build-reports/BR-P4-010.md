## 3. Root cause

P4 already possessed the authoritative closed-candle temporal concept. The defect was at the result/persistence boundary: the orchestration boundary existed as `as_of`, but persisted fact records did not expose an authoritative fact-level `knowledge_time`.

The correction therefore makes the result-level semantic explicit and preserves it at persistence without substituting `persisted_at`, `logged_at`, receipt time, commit time, current time, or wall-clock execution time.

## 4. Implementation

### Explicit result propagation

`QuantOrchestrationResult` now contains explicit `knowledge_time`.

The authoritative value is the final closed primary-candle close. Persistence validation requires UTC and:

`knowledge_time == as_of`

for the affected P4 orchestration result.

### Append-only-safe persistence

The final migration is:

`migrations/versions/0008_p4_knowledge_time_persistence.sql`

The three proven families use PostgreSQL STORED generated columns. This materializes the deterministic historical value without issuing UPDATE against append-only rows.

Structure events use:

`CASE WHEN event_type = 'ORCHESTRATION' THEN event_time ELSE NULL END`

Zones and volume profiles remain nullable because no authoritative reconstruction rule was established.

The persistence adapter validates the explicit result knowledge-time contract while allowing PostgreSQL to materialize the proven persistence value.

No identity material was changed. Existing `record_id` / `identity_hash` semantics remain stable. Existing provenance, payloads, event_time and persisted_at semantics remain untouched.

## SEMANTIC CORRECTION CYCLE — CONTROL FINDING RESPONSE

CONTROL identified that the previous implementation proved operational equality but did not independently establish authoritative semantic equivalence per family. This correction therefore re-evaluates the three affected families independently.

### Family A — calculated_indicator_vectors — CLASS-B

Authoritative chain:
CanonicalCandle.close_time → closed-candle P4-002 calculation → final indicator context timestamp → QuantOrchestrationResult.as_of → persisted event_time → earliest legitimate knowledge boundary.

P4-002 explicitly states that every candle-derived result carries the candle close timestamp and that an already-emitted observation depends only on observations up to that point. The final indicator vector is therefore authoritatively knowable at the final accepted primary candle close. This establishes knowledge_time == event_time for this family without using persisted_at, receipt time, logging time or wall-clock execution time.

### Family B — market_regime_states — CLASS-B

Authoritative chain:
CanonicalCandle.close_time → closed-candle MarketRegimeEngine validation/factors → deterministic QuantitativeContext.timestamp → QuantOrchestrationResult.as_of → persisted event_time → earliest legitimate knowledge boundary.

This conclusion is independent of the indicator family. The regime engine validates closed, ordered, non-overlapping candles; its factors use the final close and prior closes; its context is derived from the maximum candle close; and no wall-clock/receipt/persistence timestamp participates. This establishes knowledge_time == event_time for this family.

### Family C — market_structure_events / ORCHESTRATION — CLASS-C

The persisted row is an orchestration summary with event_type=ORCHESTRATION, not an individual StructuralEvent. DOC-P4-002 defines knowledge_time for actual structural facts and explicitly distinguishes event location from knowledge time, but it does not define a fact-level knowledge-time semantic for the orchestration summary row.

Therefore the equality knowledge_time == event_time is NOT authoritatively established for this family. The correct outcome is explicit unavailability, not a new semantic declaration.

The detailed evidence is recorded in docs/quantitative/P4_010_KNOWLEDGE_TIME_SEMANTIC_EVIDENCE.md.

### Migration consequence

The correction removes the previous generated-column equality for the ORCHESTRATION structure summary. Migration 0008 now materializes knowledge_time only for the two independently proven CLASS-B families; structure-summary knowledge_time remains nullable.

No P5-002 change, VPS mutation, lifecycle change, or CONTROL-owned closure synchronization was performed.
