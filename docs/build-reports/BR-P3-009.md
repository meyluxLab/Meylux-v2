## 2. Root cause

CONTROL's baseline was confirmed:

1. P3 already produces the complete governed DataQualityState space: VALID, DEGRADED, STALE, INCOMPLETE, CONTRADICTORY, REJECTED and UNAVAILABLE.
2. QualityAssessment already preserves reason codes, provenance, source-record identity and lineage where available.
3. QuarantineRecord is only a bounded routing payload and is not authoritative persistence.
4. Canonical persistence is intentionally restricted to VALID quality state.
5. The pre-existing data_quality_logs write occurs only after successful canonical insertion.
6. Therefore non-VALID outcomes can be routed away from canonical truth without obtaining a durable authoritative evidence record.
7. data_quality_logs has no dedicated authoritative knowledge_time and does not itself establish the full structured P5 EvidenceRef surface.
8. logged_at is persistence time and is not a valid knowledge-time substitute.

The correction therefore adds a separate authoritative evidence path rather than weakening canonical eligibility or P5-002.

## 3. Complete affected chain

The implemented chain is:

P2 AcquisitionEnvelope
→ P3 structural/temporal/normalization validation
→ P3 QualityAssessment
→ deterministic QualityEvidenceRecord
→ append-only quality_evidence persistence
→ deterministic read-back / logical-fact resolution
→ optional structured P5 EvidenceRef mapping.

The existing canonical path remains:

P3 QualityAssessment
→ canonical eligibility gate
→ CanonicalPersistence only for VALID evidence.

Quality evidence is now persisted before that canonical gate, so a non-VALID outcome is no longer dependent on successful canonical insertion.

## 4. Semantic model

### 4.1 Evidence fact

The authoritative quality evidence fact is the deterministic classification of one immutable P2 AcquisitionEnvelope together with the acquisition, validation, provenance and lineage inputs used to reach that classification.

It is evidence about the acquisition/validation state. It is not canonical analytical truth.

### 4.2 Time semantics

The implementation preserves:

- event_time — provider/source event time;
- received_at — acquisition observation/receipt time;
- knowledge_time — authoritative earliest boundary for this quality-evidence fact;
- persisted_at — database operational persistence time.

For the P3 quality-evidence family, the explicit semantic rule is:

knowledge_time = received_at

The equality is not copied from event_time, persisted_at, or wall-clock time. It is derived from the existing architecture: quality classification is a deterministic, side-effect-free function of the immutable acquisition evidence and explicit validation evidence. No later external observation is introduced by the P3 classifier. Therefore the receipt boundary is the earliest legitimate boundary at which the quality fact is knowable.

Late-arriving evidence remains semantically distinct:

knowledge_time > event_time

when receipt occurs after the source event.

### 4.3 Semantic chain

authoritative source
→ immutable AcquisitionEnvelope
→ received_at acquisition boundary
→ deterministic P3 validation/quality classification
→ QualityEvidenceRecord
→ event_time preserved from source
→ knowledge_time established from received_at
→ append-only persistence
→ read-back.

Persistence time never participates in the derivation.

## 5. Identity, provenance and lineage

The source identity is the existing P2 AcquisitionEnvelope event identity, which is the SHA-256 identity of the governed acquisition identity bytes.

A separate quality-evidence identity is derived from the logical fact key, source identity, quality state/lifecycle, score, reason codes, validation result, provenance/lineage, payload fingerprint, event/receipt/knowledge times and explicit context.

Consequences:

- identical replay produces identical evidence_id;
- retry is idempotent;
- the source record identity remains independently preserved;
- provenance_id remains explicit;
- lineage_parent_id remains explicit when present;
- payload fingerprint remains deterministic;
- a different quality identity for the same logical fact is retained rather than overwritten.

A logical fact with multiple distinct evidence identities is surfaced as contradiction and cannot be silently resolved.

## 6. Context / P5 EvidenceRef boundary

Explicit timeframe and venue are accepted only from payload fields:

- timeframe or interval;
- venue or venue_context.

Provider identity is preserved independently and is not silently promoted to venue.

Missing context is retained as missing. No synthetic timeframe or venue is generated.

The persistence adapter can map a resolved row to the structured P5 EvidenceRef field set:

source_family
record_id
identity_hash
event_time
knowledge_time
timeframe
venue

The resolver supports explicit consumer requirements for timeframe and venue. When a required context field is absent, resolution returns unavailable rather than manufacturing a value.

No P5-002 source code or contract was modified.

## 9. Runtime integration

The existing P3-008 vertical slice now constructs and persists QualityEvidenceRecord immediately after QualityAssessment and before the canonical eligibility return.

Therefore a non-VALID assessment is durably represented before the code returns without canonical persistence.

The existing CanonicalPersistence path remains unchanged in its core rule that canonical persistence is VALID-only.

No new truth store competing with canonical truth was introduced; the new table is specifically the authoritative evidence store required by PRQ-4.

## 10. Replay, retry and contradiction behavior

Identical input:

- same logical_fact_key;
- same evidence_id;
- second persistence is a no-op;
- no duplicate evidence row is created.

Different quality identity for the same logical fact:

- different evidence_id;
- both identities remain append-only;
- logical-fact resolution detects the contradiction;
- no silent winner is selected.

This directly covers duplicate delivery, persistence retry and contradictory evidence requirements.

## 11. Historical / legacy treatment

Existing data_quality_logs rows are preserved unchanged.

They are not automatically promoted because they lack the new authoritative knowledge_time and complete P5 context.

Historical raw acquisition observations are Class-B / deterministically reconstructible only where the preserved raw envelope is complete and the deterministic P3 validation/quality path can be rerun without external or wall-clock inputs.

Rows that cannot satisfy that reconstruction boundary remain Class-C / semantically incomplete.

No migration performs blind timestamp backfill and no historical canonical record is rewritten.
